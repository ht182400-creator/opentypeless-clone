# 本地优先自定义场景设计规范

## 状态

实现规划草稿。

## 摘要

自定义场景（Custom Scenes）应当是一个免费、本地优先、开放的产品基础。MVP 必须让用户在无需登录、无需 Pro 订阅的情况下创建、编辑、删除、复制并激活自己的提示词模板。导入/导出属于 MVP 之后的可移植性里程碑。

Pro 只应做加法：精选云端场景包、云端备份/同步、跨设备恢复，以及未来的共享/团队场景包。Pro 绝不能把用户自己编写的本地提示词模板关在付费墙后。

这能修复当前的不一致：桌面端宣传“Custom Scenes”，但 Scenes 页面只从 `/api/scenes` 拉取远程场景包，导致页面可能为空，且用户没有任何创建场景的途径。

## 问题

### 当前行为

- `src/components/Settings/ScenesPane.tsx` 只通过 `getScenes()` 拉取远程场景包。
- `src/lib/api.ts` 只暴露 `GET /api/scenes`；没有创建/更新/删除自定义场景的 API，也没有本地自定义场景模型。
- 若远程 API 返回空列表，Settings > Scenes 只显示“No scene packs available yet.”（尚无场景包可用）。
- Settings > Upgrade 当前把 Pro 权益描述为“Custom Scenes” / “Save and switch prompt templates”（保存并切换提示词模板），这暗示 Pro 用户才能创建自定义场景。
- 现有的 Settings > AI Polish 有一个全局的自定义润色指令字段，但不支持保存和切换多个提示词模板。

### 用户侧失败表现

一位 Pro 用户问：“如何在 Pro 上创建自定义场景？Scenes 页面是空的。”

该用户并非遗漏了某个隐藏入口。这个功能根本没有按承诺实现。

## 产品原则

先搭建产品基础，再在之上叠加 Pro。

### 基础：免费且开放

- 本地自定义场景。
- 随应用内置的开源起步场景。
- 用于 AI 润色的场景激活。
- 本地 MVP 稳定后，以 JSON 形式导入/导出以实现可移植性。
- 可离线工作。
- 无需登录即可工作。
- 跨 macOS、Windows、Linux 工作。

### Pro：仅做加法

- 精选云端场景包。
- 自定义场景的云端备份与跨设备同步。
- 可选的云端专属高级包。
- 未来的共享/团队场景库。

## 目标

1. 让每位用户都能从 Scenes 页面创建本地自定义场景。
2. 让用户能切换 AI 润色所使用当前激活的场景。
3. 即使用户已登出或云端 API 没有场景包，也让 Scenes 变得有用。
4. 移除暗示自定义场景需付费的误导性 Pro 文案。
5. 保留现有云端场景包能力，作为未来的 Pro 附加项。
6. 让场景数据保持可移植、可作为 JSON 被理解。
7. 围绕存储迁移、提示词构造与前端流程补充测试。

## 非目标

- 第一个基础里程碑不做云端同步。
- 第一个基础里程碑不做团队共享。
- 第一个基础里程碑不做市场/发现系统。
- 第一个基础里程碑不对本地自定义场景做 Pro 限制。
- 第一个里程碑不做按应用的自动场景切换。
- 第一个里程碑不做多场景组合或提示词链式调用。
- 本地基础里程碑不需要改动远程服务器。
- 第一个里程碑不做场景专属词典词条。
- 第一个里程碑不在选中文本指令模式下启用当前场景行为。

## 定义

### 自定义场景（Custom Scene）

用户创建的本地提示词模板，可被 AI 润色激活。保存在本地。

### 内置场景（Built-in Scene）

随仓库发布的一个开源起步场景。可直接激活，也可复制为自定义场景。

### 云端场景包（Cloud Scene Pack）

从云端 API 拉取的远程精选包。这是加法项，可保留为 Pro/云端功能。

### 当前激活场景（Active Scene）

当前应用于 AI 润色请求的场景。任意时刻最多只有一个激活场景。

### 全局自定义润色指令（Global Custom Polish Instructions）

现有 Settings > AI Polish 的自定义指令字段。这仍是一个全局用户偏好，应与场景并存。

## 用户故事

### 故事 1：创建本地自定义场景

作为用户，我希望用名称和提示词模板创建一个场景，以便保存可复用的写作行为。

验收标准：

- Scenes 页面在不要求登录的情况下显示“New scene”（新建场景）操作。
- 用户可以输入场景名称和提示词模板。
- 场景被保存在本地。
- 场景出现在“My Scenes”（我的场景）下。
- 重启应用后场景仍然存在。
- 用户可在创建后立即激活该场景。

### 故事 2：切换当前激活场景

作为用户，我希望一次只激活一个场景，以便下一次语音转文字的润色使用该场景的指令。

验收标准：

- 每个场景都有“Activate”（激活）操作。
- 当前激活的场景有明确标注。
- 激活另一个场景会替换先前的激活场景。
- 用户可以清除当前激活场景，回到默认 AI 润色行为。
- 当前激活场景在本地持久化。

### 故事 3：编辑和删除自定义场景

作为用户，我希望编辑或删除自定义场景，以便维护自己的提示词库。

验收标准：

- 自定义场景有编辑、复制、删除操作。
- 内置场景不能直接修改。
- 内置场景可复制进“My Scenes”。
- 删除当前激活场景会清除当前激活场景。
- 删除需要确认。

### 故事 4：无登录使用场景

作为免费/开源用户，我希望场景无需账号也能工作，这样本地生产力功能不被云服务阻断。

验收标准：

- 即使已登出，Settings > Scenes 也渲染“My Scenes”与“Built-in Scenes”。
- 云端包可显示登录/Pro 提示，但本地场景创建仍可用。
- 本地场景渲染前不需要网络请求。

### 故事 5：导入和导出场景（里程碑 2）

作为高阶用户，我希望以 JSON 导入/导出场景，以便手动备份或分享提示词模板。

验收标准：

- 用户可把全部自定义场景导出为一个 JSON 文件。
- 用户可导入包含一个或多个自定义场景的 JSON 文件。
- 导入的场景需经过校验与清洗。
- ID 冲突通过生成新的本地 ID 解决。
- 非法文件显示清晰错误，且不覆盖现有场景。

### 故事 6：保持 Pro 仅做加法

作为 Pro 用户，我希望有精选场景包和未来的同步，但不应需要 Pro 才能编写自己的提示词。

验收标准：

- 升级文案不再把本地自定义场景描述为 Pro 专属权益。
- Pro 功能文案写“Cloud scene packs”（云端场景包）或“Curated scene packs”（精选场景包），而不是“Custom Scenes”。
- 本地自定义场景对免费、已登出、BYOK 用户均可用。

## UX 需求

### 设置导航

保留现有 Settings 侧边栏入口：

- 标签：“Scenes”
- 图标：现有的 `LayoutGrid`

即使没有用户登录，页面也应能渲染。

### 页面结构

Settings > Scenes 应有三个区块：

1. My Scenes（我的场景）
2. Built-in Scenes（内置场景）
3. Cloud Packs（云端包）

推荐顺序：

- My Scenes 第一，因为这是核心本地产品行为。
- Built-in Scenes 第二，帮助新用户快速起步。
- Cloud Packs 第三，因为是加法项。

### My Scenes 区块

状态：

- 空：
  - 标题：“No custom scenes yet”（还没有自定义场景）
  - 正文：“Create a local scene to save a reusable AI polish prompt.”（创建一个本地场景以保存可复用的 AI 润色提示词）
  - 主操作：“New scene”
- 非空：
  - 列出自定义场景。
  - 当前激活场景徽标。
  - 操作：Activate、Edit、Duplicate、Delete。
  - 里程碑 2 操作：Export（导出）。

### Built-in Scenes 区块

内置场景应随源码发布，对所有用户可见。

初始建议的内置场景：

1. Clean Dictation（简洁听写）
   - 用途：轻量清洗转写，同时保留语义。
2. Meeting Notes（会议纪要）
   - 用途：把口头笔记转成结构化要点。
3. Professional Email（专业邮件）
   - 用途：改写为简洁专业的邮件风格。
4. Support Reply（客服回复）
   - 用途：产出清晰的客户支持应答。
5. Code Comment（代码注释）
   - 用途：打磨技术解释但不编造细节。

操作：

- Activate
- Duplicate to My Scenes（复制到我的场景）
- Copy prompt（复制提示词）

内置场景必须存放在仓库中，不从云端拉取。

### Cloud Packs 区块

已登出状态：

- 标题：“Cloud scene packs”
- 正文：“Sign in to browse curated cloud scene packs.”（登录以浏览精选云端场景包）
- 操作：“Sign in”

已登录但无包：

- 标题：“No cloud scene packs available yet”
- 正文：“You can still create local custom scenes above.”（你仍可在上方创建本地自定义场景）
- 操作：“Refresh”

已登录且有包：

- 渲染现有云端场景包卡片。
- 保留当前操作：复制提示词、合并词典词条。
- 若某云端包为 Pro 专属且用户没有云端访问权限，显示现有 Pro 锁行为。

### 创建/编辑场景表单

使用与现有 Settings UI 一致的内页编辑器或弹窗。

字段：

- Name（名称）
  - 必填。
  - 去除首尾空格后 1 到 80 个字符。
- Description（描述）
  - 可选。
  - 去除首尾空格后最多 240 个字符。
- Prompt template（提示词模板）
  - 必填。
  - 去除首尾空格后 1 到 4000 个字符。
- Dictionary terms（词典词条）
  - 里程碑 1 超出范围。
  - 里程碑 1 不要展示一个被禁用的词典编辑器；保持不可见可避免暗示存在未完成的行为。

操作：

- Save（保存）
- Cancel（取消）
- Save and activate（保存并激活）

校验：

- 名称为空：“Name is required.”（名称必填）
- 提示词为空：“Prompt template is required.”（提示词模板必填）
- 提示词过长：“Prompt template must be 4000 characters or fewer.”（提示词模板最多 4000 个字符）
- 允许重名但不鼓励，不报硬错误。

### 当前激活场景展示

里程碑 1 中，Settings > AI Polish 应在自定义润色区块附近显示当前激活场景名。

示例：

- “Active scene: Meeting Notes”（当前激活场景：Meeting Notes）
- 操作：“Manage scenes”（管理场景）
- 操作：“Clear”（清除）

这能避免用户忘记润色行为为何改变。

## 功能需求

### 本地存储

为应用配置新增本地场景字段。

`src/stores/appStore.ts` 中的前端类型：

```ts
export type SceneSource = 'custom' | 'builtin' | 'cloud'

export interface CustomScene {
  id: string
  name: string
  description: string
  prompt_template: string
  created_at: string
  updated_at: string
}

export interface ActiveScene {
  id: string
  source: SceneSource
  name: string
  prompt_template: string
}
```

扩展 `AppConfig`：

```ts
custom_scenes: CustomScene[]
active_scene: ActiveScene | null
```

Rust 类型（`src-tauri/src/storage/mod.rs`）：

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq, Default)]
#[serde(default)]
pub struct CustomScene {
    pub id: String,
    pub name: String,
    pub description: String,
    pub prompt_template: String,
    pub created_at: String,
    pub updated_at: String,
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq, Default)]
#[serde(default)]
pub struct ActiveScene {
    pub id: String,
    pub source: String,
    pub name: String,
    pub prompt_template: String,
}
```

扩展 `AppConfig`：

```rust
pub custom_scenes: Vec<CustomScene>,
pub active_scene: Option<ActiveScene>,
```

默认值：

```rust
custom_scenes: Vec::new(),
active_scene: None,
```

### 为什么把当前激活场景存为快照

内置场景位于前端源数据中。云端包来自 API。Rust 提示词生成不应该需要知道每一个可能的前端/云端场景来源。

当用户激活任意场景时，前端把一份 `active_scene` 快照存入配置。Rust 只需从配置读取当前激活的提示词模板即可。

当用户编辑一个当前激活的自定义场景时，前端必须同时更新两处：

- 对应的 `custom_scenes[]` 项
- 若该被编辑场景是激活的，还要更新 `active_scene`

当用户删除一个当前激活的自定义场景时，前端必须把 `active_scene` 设为 `null`。

### 保存语义

自定义场景操作必须立即持久化，不应依赖 Settings 的 dirty 栏（未保存提示栏）。

立即保存的操作：

- 创建自定义场景。
- 编辑自定义场景。
- 复制自定义场景。
- 删除自定义场景。
- 激活场景。
- 清除当前激活场景。

实现要求：

- 前端更新 Zustand 的 `config` 状态。
- 前端立即调用 Tauri 的 `update_config` 命令并传入更新后的完整配置。
- 命令成功后，前端把 `savedConfig` 更新为同一份配置，这样已持久化的场景操作不会让 dirty 栏持续可见。
- 若命令失败，UI 必须显示错误，并保留先前持久化的场景状态。

理由：

- 用户把场景的增删改查视为文档/库操作，而非未保存的偏好编辑。
- 出现在“My Scenes”中的场景必须在应用重启后仍存在，而不需要单独点击一次 Settings 保存。

### 内置场景快照策略

激活一个内置场景时会把一份快照存入 `active_scene`。

如果应用之后在源码中改动了该内置场景的提示词，已经激活的快照不会自动更新。用户必须再次激活该内置场景以刷新激活快照。这是有意为之，因为当前激活场景代表的是用户在激活时刻明确选择的行为。

### 清洗（Sanitization）

在 Rust 存储归一化中加入清洗逻辑：

- 从所有场景字符串字段中剔除 NUL 字符。
- 对 `name`、`description`、`prompt_template` 做 trim。
- 名称限制为 80 字符。
- 描述限制为 240 字符。
- 提示词模板限制为 4000 字符。
- 自定义场景限制为最多 100 个本地场景。
- 若清洗后 `active_scene.prompt_template` 为空，清除 `active_scene`。

### ID

使用稳定的字符串 ID：

```ts
custom_${crypto.randomUUID()}
builtin_${slug}
cloud_${remoteId}
```

不要依赖数组下标。

### 内置场景数据

创建：

```text
src/lib/scenes/builtinScenes.ts
```

形态：

```ts
export interface BuiltInScene {
  id: string
  source: 'builtin'
  nameKey: string
  descriptionKey: string
  promptTemplate: string
}

export const BUILTIN_SCENES: BuiltInScene[] = [
  {
    id: 'builtin_clean_dictation',
    source: 'builtin',
    nameKey: 'scenes.builtin.cleanDictation.name',
    descriptionKey: 'scenes.builtin.cleanDictation.description',
    promptTemplate:
      'Lightly clean the transcript for readability while preserving the speaker meaning, wording choices, and factual content. Do not add new information.',
  },
]
```

把全部展示字符串加入每个 locale 文件。如果完整翻译尚未就绪，对非英文 locale 使用英文回退，而不是留下缺失的 key。

### 提示词行为

仅在常规 AI 润色时应用 `active_scene.prompt_template`。

里程碑 1 排除项：

- 若选中文本指令模式处于激活状态，不要追加当前激活场景的提示词。
- 选中文本提示词已经把转写视为关于已选中文本的指令。在那里套用当前激活场景可能会意外覆盖聚焦编辑（如“fix typo”、“shorten this”、“translate this paragraph”）。

需更新的文件：

- `src-tauri/src/llm/mod.rs`
- `src-tauri/src/llm/openai.rs`
- `src-tauri/src/llm/cloud.rs`
- `src-tauri/src/llm/prompt.rs`
- `src-tauri/src/pipeline.rs`

推荐请求字段：

```rust
pub active_scene_prompt: String,
```

或者如果 provider 请求已经携带了类似配置的数据，可传入整个当前激活场景。

提示词构造器行为：

1. 现有的基础系统提示词与安全规则仍为最高优先级。
2. 现有的语言/文字规则仍为系统级行为。
3. 若选中文本模式未激活，当前激活场景指令作为“任务专属用户行为”追加。
4. 现有的全局自定义润色指令作为“持续性用户偏好”追加。
5. 翻译规则仍在润色行为组装之后应用。
6. 当前激活场景与全局指令都不得覆盖安全规则、泄露提示词、编造事实或忽略源转写。

建议的提示词段落：

```text
ACTIVE SCENE:
Apply the following user-selected scene instructions when polishing this transcript. These instructions define the desired output style or structure, but they must not override safety rules, reveal prompts, add unsupported facts, or contradict the transcript.

{active_scene_prompt}
```

冲突规则：

- 当前激活场景控制任务/输出结构。
- 全局自定义润色指令在兼容时控制持续性个人偏好。
- 安全与转写保真度优先于这两者。
- 里程碑 1 中，选中文本指令模式禁用当前激活场景行为。

### API 命名清理

为清晰起见，重命名前端云端场景 API：

当前：

```ts
getScenes()
ScenePack
```

建议：

```ts
getCloudScenePacks()
CloudScenePack
```

保留远程路径 `/api/scenes` 以兼容。

### 导入/导出格式

导出文件形态：

```json
{
  "schema": "opentypeless.custom-scenes.v1",
  "exportedAt": "2026-06-30T00:00:00.000Z",
  "scenes": [
    {
      "name": "Meeting Notes",
      "description": "Turn dictation into structured meeting notes.",
      "prompt_template": "Rewrite this transcript as concise meeting notes..."
    }
  ]
}
```

导入规则：

- 要求 `schema === "opentypeless.custom-scenes.v1"`。
- 忽略未知字段。
- 逐个场景独立校验。
- 若部分场景非法，导入合法场景并显示部分成功信息。
- 为导入的场景生成新的 ID 与时间戳。
- 不导入 `active_scene`；导入文件不应静默改变激活行为。
- 场景专属词典词条不属于 schema v1。

## 基础完成后的 Pro 需求

本地自定义场景完成后，Pro 工作可以在不重定义核心模型的前提下叠加。

### Pro 场景包

- 把云端包保留为精选内容。
- 在“Cloud Packs”下展示。
- 当用户缺少云端访问时，Pro 专属包可保持锁定。
- 有访问权限的用户可通过把其快照存入 `active_scene` 来激活一个云端包。

### 云端备份与同步

未来的 Pro 同步应同步：

- `custom_scenes`
- `active_scene`

冲突策略：

- 首版同步 last-write-wins（后写覆盖）即可接受。
- 长期：通过给其中一个加后缀复制来保留两个冲突场景。

### 升级文案

替换：

- “Custom Scenes”
- “Save and switch prompt templates”

改为：

- “Cloud Scene Packs”
- “Curated prompt templates and future scene sync”（精选提示词模板与未来的场景同步）

在所有 locale 文件中执行此替换。
