# Windows 修饰键安全输出修复规格与实现计划

> **面向 agent 执行者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务逐条实现本计划。步骤使用复选框（`- [ ]`）语法跟踪。

**目标：** 防止 Windows 文本注入在听写热键仍被物理按住、输出刚开始时，触发 Ctrl/Shift/Alt/Win 快捷键。

**架构：** 在 `src-tauri/src/output/` 下新增一个感知平台的修饰键释放守卫。在 Windows 上，它对 Shift、Control、Alt 以及两个 Windows 键的最高位 `GetAsyncKeyState` 位轮询最多 500 ms；在其它平台上它是空操作。每条合成文本或粘贴快捷键的路径，都在注入前立即调用该守卫；超时时退化为既有的剪贴板回退，而不是发出被破坏的按键。

**技术栈：** Rust 2021、Tauri 2、`windows-sys` 0.59、Enigo 0.2.1、Cargo 单元测试。

## 全局约束

- 保留现有热键语义：toggle 模式仍在 `ShortcutState::Pressed` 上开始与停止；hold 模式仍在松开时停止。
- 不要合成修饰键的 key-up 事件，因为那样会覆盖用户故意按住的修饰键。
- 在做出安全回退前，最多等待 500 ms，每 10 ms 轮询一次。
- 只检查 `GetAsyncKeyState` 的最高位；低位“自上次查询以来按下过”的位是明确不可靠的。
- 守卫所有自动化的 Windows 输入路径：Enigo 文本、显式 Windows SendInput、以及模拟剪贴板粘贴。
- 通过非 Windows 的空操作实现，保持 macOS 与 Linux 行为不变。
- 不新增依赖；`windows-sys` 已启用 `Win32_UI_Input_KeyboardAndMouse`。

---

## 问题陈述与根因

GitHub issue [#80](https://github.com/tover0314-w/opentypeless/issues/80) 报告了在 Windows 11 上、toggle 模式、键盘模拟、`Ctrl+Space` 场景下间歇性的文本损坏。存储在 history 中的转写是正确的，而 Firefox/Zen Browser 收到的却是 Markdown 快捷键效果，如加粗与斜体标记。

相关的事件序列是：

1. 第二次 `Ctrl+Space` 产生一个 Windows `WM_HOTKEY` 按下事件。
2. `recording_shortcut_action()` 把 toggle 模式的按下事件映射为 `RecordingShortcutAction::Stop`，而不等待松开。
3. 一个快速的 STT 响应在 Ctrl 仍可能被物理按住时到达 `KeyboardOutput::type_text()`。
4. Enigo 0.2.1 通过 `SendInput` 发出 Windows Unicode 键盘事件，而不检查已有的修饰键状态。
5. 目标应用把受影响的字母解释成 Ctrl 快捷键，尽管 Unicode 负载本身是正确的。

这与微软的 `SendInput` 契约一致：该 API 不会重置当前键盘状态，已被按下的键可能产生干扰，调用方应当检查 `GetAsyncKeyState`。参考地址为 <https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput>。

`PipelineHandle::stop()` 中现有的 60 ms 延迟以 `selected_text_enabled` 为条件；其默认值为 `false`，因此它不保护普通的键盘输出。把固定的 sleep 移入 pipeline 也会让显式 SendInput、剪贴板粘贴、流式插入以及未来的直接调用方仍处于脆弱状态。

## 验收标准

- 当 Windows 输出开始时 Ctrl 处于按下状态、并在 500 ms 内松开时，在它松开之前不发出任何合成文本/粘贴事件。
- Shift、Alt、左 Win、右 Win 获得同样的保护。
- 当某个修饰键持续按下达到 500 ms 时，直接的键盘/SendInput 输出返回 `AppError::Output`；既有的策略回退把完整文本复制，而不是在修饰键下把它打出来。
- 当剪贴板粘贴是激活/回退策略且某个修饰键仍按下时，跳过粘贴快捷键，既有的 `CopiedFallback` 结果把完整文本留在剪贴板上。
- 当没有修饰键按下时，守卫不睡眠。
- macOS 与 Linux 保留其当前行为。
- 既有的 Rust 测试、Clippy、格式化以及前端测试套件继续通过。

- [ ] **步骤 3：实现最小的共享守卫**

把新文件替换为：

```rust
use crate::error::AppError;

#[cfg(target_os = "windows")]
const MODIFIER_RELEASE_POLL_INTERVAL_MS: u64 = 10;
#[cfg(target_os = "windows")]
const MODIFIER_RELEASE_MAX_WAIT_CYCLES: usize = 50;

#[cfg(any(target_os = "windows", test))]
fn wait_until_modifiers_released(
    mut any_modifier_is_down: impl FnMut() -> bool,
    mut pause: impl FnMut(),
    max_wait_cycles: usize,
) -> bool {
    for cycle in 0..=max_wait_cycles {
        if !any_modifier_is_down() {
            return true;
        }
        if cycle < max_wait_cycles {
            pause();
        }
    }
    false
}

#[cfg(target_os = "windows")]
fn any_modifier_is_down() -> bool {
    use windows_sys::Win32::UI::Input::KeyboardAndMouse::{
        GetAsyncKeyState, VK_CONTROL, VK_LWIN, VK_MENU, VK_RWIN, VK_SHIFT,
    };

    [VK_SHIFT, VK_CONTROL, VK_MENU, VK_LWIN, VK_RWIN]
        .into_iter()
        .any(|virtual_key| unsafe { GetAsyncKeyState(virtual_key as i32) } < 0)
}

#[cfg(target_os = "windows")]
pub fn wait_for_modifier_release() -> Result<(), AppError> {
    let released = wait_until_modifiers_released(
        any_modifier_is_down,
        || {
            std::thread::sleep(std::time::Duration::from_millis(
                MODIFIER_RELEASE_POLL_INTERVAL_MS,
            ));
        },
        MODIFIER_RELEASE_MAX_WAIT_CYCLES,
    );

    if released {
        Ok(())
    } else {
        Err(AppError::Output(
            "Windows modifier keys remained pressed for 500 ms; skipped simulated input"
                .to_string(),
        ))
    }
}

#[cfg(not(target_os = "windows"))]
pub fn wait_for_modifier_release() -> Result<(), AppError> {
    Ok(())
}

#[cfg(test)]
mod tests {
    use super::*;
    use std::collections::VecDeque;

    #[test]
    fn waits_until_pressed_modifiers_are_released() {
```
