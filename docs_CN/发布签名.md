# 发布签名配置

OpenTypeless 的构建在 `toverwu-qaq/opentypeless` 进行，并发布到 `tover0314-w/opentypeless`。

## 必需的 GitHub Secrets

这些 Secret 需要配置在 `toverwu-qaq/opentypeless` 上，因为该仓库运行 GitHub Actions 工作流。

macOS：

- `APPLE_CERTIFICATE`
- `APPLE_CERTIFICATE_PASSWORD`
- `APPLE_SIGNING_IDENTITY`
- `APPLE_ID`
- `APPLE_PASSWORD`
- `APPLE_TEAM_ID`

Tauri 更新器：

- `TAURI_SIGNING_PRIVATE_KEY`
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`

跨仓库发布：

- `RELEASE_TOKEN`

Linux：

- `LINUX_GPG_PRIVATE_KEY`：base64 编码的 ASCII  armored 私钥
- `LINUX_GPG_KEY_ID`：GPG 密钥 ID 或指纹
- `LINUX_GPG_PASSPHRASE`：GPG 密钥口令

Windows PFX 备选：

- `WINDOWS_CERTIFICATE`：base64 编码的 PFX 代码签名证书
- `WINDOWS_CERTIFICATE_PASSWORD`：设置 `WINDOWS_CERTIFICATE` 时必填
- `WINDOWS_TIMESTAMP_URL`：可选的时间戳服务器 URL；默认为 DigiCert

当 PFX 签名 Secret 缺失时，通用的 `Release` 工作流会拒绝构建或发布 Windows 产物。仅当配置了受信任的 PFX 证书时，才使用该工作流发布 Windows。否则，请通过下面专门的 `Release Windows SignPath` 工作流发布 Windows。默认情况下，未签名和测试签名的安装包会被阻止公开发布。

如需临时特例，手动触发工作流时可把 `allow_unsigned_windows` 设为 `true`。该选项是默认关闭的，也是唯一允许通用工作流发布未签名 Windows 安装包的路径。由标签触发和普通手动发布仍会"失败即关闭"（fail closed）。

Windows SignPath：

- `SIGNPATH_API_TOKEN`：作为所选签名策略提交者的 SignPath 用户令牌
- `SIGNPATH_ORGANIZATION_ID`：SignPath 组织 ID
- `SIGNPATH_PROJECT_SLUG`：SignPath 项目 slug
- `SIGNPATH_SIGNING_POLICY_SLUG`：SignPath 签名策略 slug

SignPath 项目与 GitHub 受信任构建系统必须指向 `toverwu-qaq/opentypeless`，因为该仓库运行 GitHub Actions 工作流，并拥有提交给 SignPath 的 GitHub 产物。签名后的 Windows 产物仍会发布到 `tover0314-w/opentypeless`。

Windows SignPath 工作流使用项目的默认产物配置。该默认产物配置必须以 `<zip-file>` 为根，因为 GitHub 的 `actions/upload-artifact` 动作以 ZIP 归档方式存储文件。

slug 以 `test-` 或 `test_` 开头的签名策略仅用于空跑（dry-run）。它们可以验证"构建到 SignPath"的集成，但工作流会拒绝将这些安装包发布到生产环境的 GitHub Release。发布需要使用 Authenticode 结果为 `Valid` 的生产环境 SignPath 策略。

要在没有 PFX 证书的情况下完成完整发布，请分别为 `macos` 和 `linux` 单独触发通用的 `Release` 工作流，然后将 `Release Windows SignPath` 的 `publish_release` 设为 `true`。在配置受信任的 Windows PFX 证书之前，不要使用通用工作流的 `all` 选项，因为其 Windows 任务会有意"失败即关闭"。

## Windows 证书说明

请使用真实的代码签名证书。SSL/TLS 证书不能用于签署 Windows 桌面应用。EV 证书可立即获得 Microsoft SmartScreen 信誉；OV 证书在信誉建立之前仍可能显示 SmartScreen 警告。

如果你拿到 `.pfx` 文件，在保存为 GitHub Secret 之前需先编码：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("certificate.pfx")) |
  Set-Content -NoNewline windows-certificate-base64.txt
```

将 `windows-certificate-base64.txt` 的内容保存为 `WINDOWS_CERTIFICATE`。

## Linux GPG 说明

生成一个仅用于发布的 GPG 密钥，导出并做 base64 编码：

```bash
gpg --full-gen-key
gpg --armor --export-secret-keys "OpenTypeless Release" > opentypeless-linux-private.asc
openssl base64 -A -in opentypeless-linux-private.asc -out opentypeless-linux-private.asc.base64
gpg --list-secret-keys --keyid-format LONG
```

将 `opentypeless-linux-private.asc.base64` 保存为 `LINUX_GPG_PRIVATE_KEY`，指纹/密钥 ID 保存为 `LINUX_GPG_KEY_ID`，口令保存为 `LINUX_GPG_PASSPHRASE`。

工作流会内嵌 AppImage 签名，通过 Tauri 对 RPM 包签名，为 Linux 产物创建分离的 `.asc` 签名，并上传架构相关的校验和清单，例如 `SHA256SUMS-linux-x86_64.txt` 与 `SHA256SUMS-linux-aarch64.txt`。
