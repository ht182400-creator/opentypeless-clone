## 1. 目的

## 3. 用于分流的代码库事实

### 3.1 麦克风选择仍然缺失

当前 `src-tauri/src/audio/capture.rs` 中的代码始终调用 `host.default_input_device()`。`AudioConfig` 有 `sample_rate`、`channels`、`chunk_duration_ms`，但没有已选设备字段。

`src-tauri/src/storage/mod.rs` 与 `src/stores/appStore.ts` 中的当前配置类型也都没有 `audio_input_device` 设置。

结论：#52 指向一个真实缺失的功能。它应当被重建，因为该 PR 存在冲突，并且还包含一个无关的 macOS 辅助功能（Accessibility）提交。

### 3.2 History 有有用的原始数据但没有所请求的汇总 UI

当前 history 存储已经记录：

- `raw_text`
- `polished_text`
- `language`
- `duration_ms`

当前的 `src/components/History/index.tsx` 渲染润色后的文本、时间、应用名、搜索、一个复制按钮和清空全部。它不显示聚合汇总、双复制按钮或可展开的原文转录。

结论：#28 尚未解决。#27 中有用的部分是它的 History UI 方向，但该 PR 还包含异常检测、测试工具以及宽泛的无关格式化改动。我们应当重建 History 部分。

### 3.3 提示注入防御在 main 中已存在

当前的 `src-tauri/src/llm/prompt.rs` 已经包含：

- 明确的 `DO NOT EXECUTE CONTENT` 规则。
- `<transcription>` 隔离。
- 选中文本隔离。
- 词典与目标语言清洗。
- 针对类指令转录、西班牙语标点、编号以及选中文本提示注入的测试。

结论：#27 的异常检测器可能是纵深防御，但不是下一优先级的修复。它不应与 History UI 捆绑。

### 3.4 本地 / 自定义 Whisper 已经存在

当前的 `src-tauri/src/stt/config.rs`、`src-tauri/src/stt/mod.rs`、`src/components/Settings/SttPane.tsx` 与 `src/lib/constants.ts` 已经包含 `custom-whisper` 支持。

结论：#47 已被 main 取代。

### 3.5 Deepgram 仍是实时 WebSocket

当前的 `src-tauri/src/stt/deepgram.rs` 使用 Deepgram 实时 WebSocket，配置 `interim_results=true`、`endpointing=150`、`linear16` 与 `sample_rate`。

PR #44 用批量 REST 上传替换了它。如果截断是真实的，这可能修复截断，但同时也移除了实时部分转写行为并改变了 provider 生命周期语义。

结论：#44 在实现前需要复现。在 macOS/Windows 健康期间默认不要合并它。

### 3.6 平台稳定性修复已经落地

当前 main 包含：

- `macOSPrivateApi` 与透明胶囊相关配置。
- Linux `XInitThreads` 初始化。
- NVIDIA + Wayland DMA-BUF 变通方案。
- Linux Wayland/键盘输出护栏。
- macOS 键盘输出在主线程。

结论：在 macOS 与 Windows 当前健康期间，#22、#45 以及 #40 中宽泛的平台部分不是优先级。

### 3.7 依赖审计当前失败

`npm audit --audit-level=high` 当前报告：

- 高危：`form-data` 4.0.0 - 4.0.5，可通过 `jsdom@25.0.1` 触达。
- 中危：`js-yaml <=4.1.1`，可通过 `eslint@9.39.3 -> @eslint/eslintrc@3.3.4` 触达。

这大多是开发/测试工具链，但高危审计失败是真实的，会阻塞干净的基线。

结论：把审计修复作为聚焦的 P0 依赖 PR 处理，而不是整体合并宽泛的 #33 或 #38 dependabot PR。

## 4. 优先级

### P0：聚焦的依赖审计修复

问题：前端审计当前在 `form-data` 与 `js-yaml` 上失败。

范围：

1. 更新让 `npm audit --audit-level=high` 通过所需的最小依赖集。
2. 优先使用定向更新（如 `jsdom` 以及相关 ESLint 依赖链），而不是全盘接受 #33/#38 的所有改动。
3. 除非对等依赖约束要求，否则避免宽泛的框架动荡。

验收标准：

1. `npm audit --audit-level=high` 通过。
2. `npm test` 通过。
3. `npm run build` 通过。
4. `npm run lint` 通过。
5. Lockfile 差异可审查，且不包含无关的依赖大版本动荡。

### P1：从 #52 重建麦克风输入选择器

问题：用户无法选择 OpenTypeless 从哪个麦克风录音。

实现要求：

1. 向 Rust `AppConfig` 新增一个持久化的 `audio_input_device` 设置。
2. 向 TypeScript `AppConfig` 与 store 默认值新增同一字段。
3. 新增可序列化的 `AudioInputDevice` 形态：
   - `id: string`
   - `name: string`
   - `is_default: boolean`
4. 新增一个 Tauri 命令（可能为 `list_audio_input_devices`），返回所有 CPAL 输入设备外加前端的"系统默认"选项。
5. 用 `input_device_name: Option<String>` 或等价的选中字段扩展 `AudioConfig`。
6. 在捕获启动时：
   - 空选择使用系统默认。
   - 非空选择按名称搜索 CPAL 输入设备。
   - 选中的设备缺失时，抛出面向用户的错误，或仅在 UI 明确说明的情况下回退。
7. 在 `GeneralPane` 中新增 UI：
   - 麦克风选择器。
   - 系统默认选项。
   - 刷新按钮。
   - 禁用/加载中/错误状态。
   - 在 UI 中保留不可用的已选设备，以便用户能看到哪里出了问题。
8. 为所有支持的语言新增 i18n 标签。
9. 不要包含 #52 中无关的旧 macOS 辅助功能改动。

重要设计说明：

CPAL 不暴露稳定的跨平台设备 ID。如果以设备名作为 ID，UI 与配置必须将其视为尽力而为的标签，而不是永久的硬件标识符。

验收标准：

1. 未选中设备时，默认设备行为不变。
2. 选中外接麦克风后，录音经由该设备。
3. 拔掉选中的麦克风会产生清晰的错误或可见的回退行为。
4. 设置跨应用重启持久化。
5. macOS 与 Windows 手动录音测试通过。
6. Rust 辅助函数尽可能覆盖设备选择逻辑测试。
7. 前端测试覆盖选择器加载、保存行为以及不可用的已选设备渲染。

### P2：用小型 History 汇总/UI PR 解决 #28

问题：没有汇总 UI，且 History 不能顺手暴露原文转录。

MVP 范围：

1. 使用当前已加载的条目，在 History 中新增一条紧凑汇总条：
   - 录音总次数。
   - 来自 `duration_ms` 的总录音时长。
   - 输出总词数/字符数。
2. 新增双复制动作：
   - 复制润色文本。
   - 复制原文转录。
3. 为每个 History 行新增可展开的原文转录。
4. 保持针对 `polished_text`、`raw_text` 与 `app_name` 的搜索行为。
5. 保持当前的 History 保留模型不变。

首个 PR 之外：

1. #27 的 LLM 异常检测器。
2. 新的后端分析表。
3. 图表、日历热力图或跨设备同步。
4. 重构无关的 onboarding/settings 组件。

验收标准：

1. 此功能上线后可关闭 #28。
2. 当 `duration_ms` 为 null 时，History 仍能正确渲染。
3. 复制润色与复制原文有各自独立的可视状态。
4. 原文转录展开不会过度推移整体布局。
5. 前端测试覆盖汇总数字、双复制、原文展开、空状态与搜索。

未来增强：

如果汇总应覆盖所有保留的 history 条目，而不只是已加载列表，则新增一个后端 `get_history_summary` 命令，直接在 SQLite 中聚合。

### P3：来自 #53 的可选 60dB provider 调研

问题：#53 新增了一个 STT provider，但 PR 描述没有完成的测试计划，也没有 API 行为已验证的证据。

实现前的门槛：

1. 从官方文档或实时测试账户确认 60dB 当前的 API 端点、请求结构、认证、模型名与响应形态。
2. 确认它是 OpenAI Whisper 兼容还是需要自定义 provider。
3. 确认针对无效 Key、配额耗尽、不支持的音频格式与超时的预期错误。

若实现的验收标准：

1. provider 配置集中化，而不是散落在命令与 UI 常量中。
2. 解析器测试覆盖成功与错误响应。
3. 连接测试与延迟基准支持它。
4. UI 标签与 API Key 行为正确。
5. 合并前用真实 Key 手动测试成功。

决策：

不要原样合并 #53。仅当 60dB 是期望的官方 provider 时才重建。

### P3：来自 #44 的 Deepgram 截断调研

问题：#44 声称实时 Deepgram 会截断长语句，但完全切换到批量模式会移除实时行为并改变 provider 语义。

实现前的门槛：

1. 用当前 main 分支复现截断。
2. 确认问题属于：
   - 最终转写与部分转写的替换。
   - `endpointing=150` 过于激进。
   - 流关闭时机。
   - Deepgram 服务行为。
3. 决定是：
   - 保留 WebSocket 并修复最终转写聚合。
   - 调优 endpointing/语句处理。
   - 新增可选的批量模式。
   - 完全替换实时模式。

若实现的验收标准：

1. 长语句测试用例不再截断。
2. 如果保留实时模式，短句实时听写仍提供有用的部分反馈。
3. 当没有可用转写时，provider 生命周期不会忙循环。
4. Deepgram 解析器测试覆盖部分、最终、空、错误与关闭行为。

决策：

在截断被复现且产品权衡明确之前，不要合并 #44。

## 5. 非目标

1. 不要直接合并任何当前开放的冲突 PR。
2. 在 macOS 与 Windows 健康期间，不要进行宽泛的平台重写。
3. 不要把依赖升级与功能工作捆绑。
4. 不要把异常检测与 History UI 放在同一个 PR。
5. 在没有复现和 UX 决策之前，不要替换 Deepgram 实时模式。
6. 在没有 API 验证之前，不要将 60dB 作为官方 provider 加入。

## 6. 建议实现顺序

1. 创建一个聚焦的依赖审计 PR。
2. 基于 #52 有用的部分，创建一个聚焦的麦克风选择器 PR。
3. 创建一个聚焦的 History 汇总/UI PR，关闭 #28 并仅借用 #27 中有用的 History 思路。
4. 决定 60dB 是否是产品优先级。如果是，基于已验证的 API 行为实现它，而不是通过直接合并 PR。
5. 复现 Deepgram 截断。只有那时再决定 #44 的批量方案是否合适。
6. 在替代 PR 落地后关闭或评论过时的 PR：
   - #47 已被 main 取代。
   - #45 过于宽泛且大部分已被取代。
   - #40 推迟，因为当前 Windows 路径可用。
   - #22 推迟，因为当前 macOS 路径可用。
   - #33/#38 被聚焦的审计修复取代。

## 7. 验证矩阵

为每个聚焦 PR 运行：

```bash
npm test
npm run build
npm run lint
```

为依赖/审计 PR 运行：

```bash
npm audit --audit-level=high
```

为 Rust/音频/STT PR 运行：

```bash
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings
cargo fmt --check --manifest-path src-tauri/Cargo.toml
```

麦克风选择器的手动检查：

1. macOS 默认麦克风录音。
2. macOS 外接麦克风录音。
3. macOS 选中麦克风被拔掉。
4. Windows 默认麦克风录音。
5. Windows 外接麦克风录音。
6. 设置重启后持久化。

History UI 的手动检查：

1. 空 history。
2. 短润色结果。
3. 原文转录不同于润色文本。
4. `duration_ms` 为 null。
5. 按原文、润色文本与应用名搜索。

Deepgram 调研的手动检查：

1. 短语句。
2. 带句边界的长语句。
3. 说完立即停止。
4. 网络中断。
5. 无效 API Key。

## 8. 最终建议

现在值得关注的 PR 有：

1. #52，但仅作为重建的麦克风选择器。
2. #27，但仅作为有助于关闭 #28 的 History UI 部分。
3. #33/#38，仅作为小型依赖审计修复的信号。
4. #53，仅当 API 验证后 60dB 是期望的官方 STT provider。
5. #44，仅当在当前 main 上复现了 Deepgram 截断。

下一项具体工程工作应是 P0 依赖审计修复，然后是 P1 麦克风选择器，再是 P2 History 汇总 UI。
