# OpenTypeless AppSumo 终身云客户端规格

日期：2026-06-20
项目：`opentypeless`
伴随规格：`talkmore/docs/2026-06-20-appsumo-lifetime-cloud-api-spec.md`
状态：在 AppSumo 定价批准之后建议实现

## 1. 执行摘要

OpenTypeless 需要一次客户端 AppSumo 就绪改造，让终身买家理解他们的云权益是每月云字数，而不是 STT 小时或 LLM tokens。桌面 app 应保留 BYOK 作为无限/私有的路径，而托管云路径变成清晰的 AppSumo 权益，配单一用量计、可预测的超额行为，以及与 AppSumo 上架文案一致的措辞。

可安全上线的 AppSumo 方案是三个license 档位的终身交易：

| 档位 | 价格 | 每月云字数 | 定位 |
| -------------- | ----: | --------------------: | ----------------------------- |
| License Tier 1 |   $59 |               200,000 | 个人日常听写 |
| License Tier 2 |  $149 |               700,000 | 重度用户与重度写作 |
| License Tier 3 |  $299 |             1,250,000 | 创始人/运营者重度使用 |

这在不过度暴露云 COGS 的情况下，与当前 AppSumo 语音写作交易有竞争力。WriteVoice 列出 $59/$139/$249 对应 200,000/500,000/1,250,000 每月听写字数。AI Dictation 以 $49 码堆叠，前四级为 200k/400k/800k/1.2m 字数。VoiceDash 列出 $59/$149/$299/$499 对应 200k/600k/1.4m/3m 每月字数并含团队功能。Letterly 是例外，有 $89+ 终身码且无字数上限，但其经济与定位差异足够大，OpenTypeless 不应在没有更强本地/离线成本控制的情况下照搬“无限云”。仅在 payout 与 COGS 被证明后，才可测试 $329-349 对应 1,500,000 字数的拉伸 Tier 3。

## 2. 当前客户端基线

对照本地 `main` 评审，其与 `origin/main` 在提交 `1cfda30 docs: improve github conversion` 对齐。工作区有不相关的本地改动，所以本规格应在新分支实现，不回退既有编辑。

今天的相关实现：

1. `src/lib/api.ts`
   - `SubscriptionStatus` 仅支持 `plan: 'free' | 'pro'`。
   - 状态负载拆分为 `sttSecondsUsed`、`sttSecondsLimit`、`llmTokensUsed`、`llmTokensLimit`。
   - `proxyLlm()` 只发送 `messages`；不向 TalkMore 发送 mode 元数据。
2. `src/stores/authStore.ts`
   - Auth state 镜像 token/小时配额模型。
   - 在 90% 时分别为 STT 与 LLM 触发配额警告。
3. `src/components/AccountPage/index.tsx`
   - 账户详情只显示 Free/Pro。
   - 配额卡片显示两条 bar：STT 小时/分钟 与 LLM k tokens。
   - 订阅管理假设所有付费用户都走 Pro 订阅门户。
4. `src/components/UpgradePage/index.tsx`
   - 升级卡片显示 `$4.99 / month`。
   - Pro 配额卡片使用 STT 小时与 LLM tokens。
5. `src/components/Settings/LlmPane.tsx`
   - 云 LLM 卡片写 “Cloud LLM (Pro)” 并使用 Pro 订阅文案。
6. `src-tauri/src/llm/cloud.rs`
   - 本地构建系统 prompt 与 messages，然后发送 `{ messages, stream }` 到 `/api/proxy/llm`。
   - 检测 403 配额错误并映射为 `AppError::LlmQuota`。
   - 不把 app 类型、选中文本模式、翻译状态或配额意图元数据作为独立字段发送。
7. `src-tauri/src/stt/cloud.rs`
   - 上传 WAV 音频到 `/api/proxy/stt`。
   - 检测配额形态的 403 响应并映射为 `AppError::Quota`。
8. `src-tauri/src/commands/stt.rs`
   - 云 STT 与云 LLM 连接测试调用 `/api/subscription/status`。
   - 两个云测试当前只把 `plan === "pro"` 当作活跃云访问，所以除非改掉，否则 AppSumo 套餐会通不过连接检查。
9. `src/components/Onboarding/LlmSetupStep.tsx` 与 `src/components/Onboarding/SttSetupStep.tsx`
   - Onboarding 仍渲染面向 API key 的字段，并在 API key 为空时禁用测试按钮。
   - 云 onboarding 必须使用 sign-in 加权益状态，而非本地 API key。
10. `src-tauri/src/llm/prompt.rs`

- Prompt 已有有用的产品差异化：app 感知格式化、自定义词典、翻译、选中文本命令模式，以及 prompt 注入防护。
- 普通转写被正确地当作仅是内容；口头命令应仅在选中文本模式有真实选中文本时才执行。

## 3. 产品决策评审

AppSumo 方案不应实现成“当前 Pro，但终身”。这个捷径会造成两个问题：

1. 面向用户的数值仍会令人困惑，因为 app 还是会显示小时与 tokens。
2. 终身买家、月度订阅者、退款状态与未来升级都会共享一个 `pro` 标志，造成权益 bug 的可能性高。

客户端决策：

1. 把 AppSumo 当作独立的付费来源：`source: 'appsumo'`。
2. 把 words/month 当作规范化的面向用户配额。
3. 让 BYOK 在视觉上分开且无限。
4. 在产品 UI 中隐藏精确的云模型名。
5. 保留当前月度 Pro 订阅，直到独立的定价决策替换它。

## 4. 目标

1. 在 Account 与 Upgrade 界面展示 AppSumo license 档位、云字数已用、云字数上限与重置日期。
2. 用单一的云字数计替换面向客户的“STT 小时”与“LLM k tokens”，用于托管云用量。
3. 让超额行为可理解：云配额用尽，切换到 BYOK 或等待重置。
4. 在 rollout 期间与既有 TalkMore 状态响应保持向后兼容。
5. 让选中文本模式行为显式且可测。
6. 向 TalkMore 发送足够的请求元数据，让服务端能准确路由模型与配额，而不只解析 prompt。
7. 在桌面 UI 中避免承诺无限的托管云用量。

## 5. 非目标

1. 除非 web 流程不可用，否则不在桌面 app 实现 AppSumo license 激活。激活应主要发生在 opentypeless.com。
2. 不移除 BYOK provider。
3. 不向最终用户暴露模型名、token 数或 provider 内部细节。
4. 本 AppSumo 客户端 pass 不在 OpenTypeless 实现团队席位。
5. 本 AppSumo 客户端 pass 不增加离线/本地模型功能。

## 6. 目标用户

主要用户：

1. 想要登录后“开箱即用”云听写与 AI 润色的 AppSumo 买家。
2. 在邮件、文档、聊天、浏览器 app 的普通桌面文本字段中使用 OpenTypeless。
3. 以 words/month 思考，而不是秒、tokens 或 provider 模型。

次要用户：

1. 既有开源/BYOK 用户。
2. 想用自己的 API key 获得无限/私有用量。
3. 不应感觉被强迫进云或 AppSumo。

## 7. 用户故事与需求

### 故事 1：AppSumo 买家看到自己的真实 license

作为 AppSumo 买家，我希望 Account 展示我的终身 license 档位与字数配额，这样我能信任 app 已连上我的购买。

验收标准：

1. Account 页展示套餐名：
   - `Free`
   - `Pro`
   - `AppSumo Tier 1`
   - `AppSumo Tier 2`
   - `AppSumo Tier 3`
2. AppSumo 账户显示 `Lifetime license`，而不是 `Renews`。
3. AppSumo 账户展示每月云字数的 `Resets on <date>`。
4. 月度订阅者仍可访问计费门户。
5. 除非 TalkMore 返回有效的 license 管理 URL，否则 AppSumo 用户看不到通用的 “Manage subscription” 门户按钮。

### 故事 2：用户看到单一的云字数计

作为云用户，我希望看到单一的每月云字数计，这样我知道我包含的 AppSumo 用量还剩多少。

验收标准：

1. Account 与 Upgrade 页展示：
   - `Cloud words this month`
   - `<used> / <limit> words`
   - 重置日期（若可用）
2. 桌面 app 不再为 AppSumo 套餐显示 `quotaHours` 或 `quotaTokens`。
3. 遗留 Pro 用户可能仍收到服务端 STT/LLM 字段，但当存在时 UI 应优先 `cloudWordsUsed` 与 `cloudWordsLimit`。
4. 在云字数 90% 时，显示一条警告 toast。
5. 在 100% 时，显示一条超额 toast，且不显示独立的 STT/LLM 警告。

### 故事 3：用户理解 BYOK 是分开的

作为重度用户，我希望 BYOK 保持无限且私有，这样在托管云配额用尽后我还能继续用 OpenTypeless。

验收标准：

1. Account 或 Upgrade 页包含一行短句：
   - `BYOK usage is unlimited and does not count toward cloud words.`
2. Settings 应保持本地 API key provider 可见。
3. 超额错误包含直接打开 Settings 并把 STT/LLM provider 切到 BYOK 的动作。
4. BYOK 文案不得暗示 AppSumo 包含无限的托管云用量。

### 故事 4：Settings 文案与 AppSumo 方案一致

作为选择 provider 的用户，我希望云模式文案与我购买的套餐一致，这样我理解为什么 sign-in 重要。

验收标准：

1. STT 云卡片与 LLM 云卡片文案使用 “Cloud words” 与 “included monthly usage”。
2. 免费用户文案说云试用/积分，而不是仅 Pro。
3. 付费 AppSumo 用户文案说云已激活。
4. 月度 Pro 用户文案仍说云已激活。
5. UI 不在面向客户的套餐卡片中提到 Gemini、Groq、OpenRouter、tokens 或小时。

### 故事 5：客户端发送 mode 元数据供服务端路由

作为云 API，我需要关于请求模式的元数据，这样能正确路由模型回退与配额。

验收标准：

1. `CloudLlmProvider` 发送向后兼容的请求体：
   ```json
   {
     "messages": [],
     "stream": true,
     "context": {
       "operationId": "018f9a9b-7c3e-7b1a-a2f3-2e1b8a6a8f10",
       "appType": "email",
       "hasSelectedText": true,
       "translateEnabled": false,
       "targetLang": "en",
       "rawTextChars": 123,
       "selectedTextChars": 456
     }
   }
   ```
2. TalkMore 必须继续接受没有 `context` 的旧客户端。
3. context 值不得包含实际的选中文本或转写，除非在既有 `messages` 负载中。
4. `operationId` 每次录音/语音 pipeline 生成一次，并复用于匹配的云 STT 与云 LLM 调用，这样 TalkMore 能一次性结算面向客户的云字数。
5. Rust `AppType` 必须显式映射为小写字符串：`email`、`chat`、`code`、`document`、`general`。
6. 测试覆盖选中文本与非选中文本流的序列化 context。

### 故事 6：配额错误可操作

作为用户，我希望云配额错误告诉我发生了什么以及下一步做什么。

验收标准：

1. STT 配额错误展示：
   - `Cloud words used up. Switch to BYOK or wait until your monthly reset.`
2. LLM 配额错误展示同样的云字数框架。
3. 错误 UI 应在当前通知/toast 模式允许的地方包含 Settings 动作。
4. 鉴权错误与配额错误保持分开。
5. 空或未知的 403 响应体仍保持鉴权错误，与当前 `cloud.rs` 行为一致。

### 故事 7：云 onboarding 与连接测试支持 AppSumo

作为 AppSumo 买家，我希望首次设置与连接测试识别我的终身 license，这样激活后不会被阻塞。

验收标准：

1. 云 STT 与云 LLM 连接测试使用共享的付费云访问规则，而不是 `plan === "pro"`。
2. 当 `source: "creem"` 有正的 `cloudWordsLimit`，或 `source: "appsumo"` 有正的 `cloudWordsLimit` 且 `licenseStatus: "active"` 时，付费云套餐激活。
3. Onboarding 云 provider 步骤不要求本地 API key。
4. 若用户未登录，onboarding 在云测试前把他们引到账户 sign-in。
5. 若云配额耗尽，onboarding 解释 BYOK 或月度重置，而不是展示通用连接失败。
6. 测试覆盖 Free、Pro、AppSumo Tier 1、已退款 AppSumo 与未知套餐响应。

## 8. API 契约

OpenTypeless 应接受新的 TalkMore 状态形态：

```ts
type SubscriptionStatus = {
  plan: 'free' | 'pro' | 'appsumo_tier1' | 'appsumo_tier2' | 'appsumo_tier3'
  source: 'free' | 'creem' | 'appsumo'
  displayName: string
  subscriptionEnd: string | null
  subscriptionStatus: string | null
  licenseStatus?: 'active' | 'refunded' | 'deactivated' | 'pending'
  cloudWordsUsed: number
  cloudWordsLimit: number
  cloudWordsResetAt: string | null
  byokUnlimited: true

  // 在 rollout 期间的向后兼容：
  sttSecondsUsed?: number
  sttSecondsLimit?: number
  llmTokensUsed?: number
  llmTokensLimit?: number
}
```

客户端兼容规则：

1. 若 `cloudWordsLimit` 存在，使用云字数 UI。
2. 若不存在，回退到当前 STT/LLM bar。
3. 未知套餐 ID 不应自动解锁云。客户端仅在 `source` 为 `creem` 且 `cloudWordsLimit > 0`，或 `source` 为 `appsumo` 且 `cloudWordsLimit > 0` 且 `licenseStatus === "active"` 时，才可显示 `Paid plan detected`。
4. `plan === 'pro'` 不能是唯一的付费检查。增加一个 helper 如 `hasManagedCloudAccess(status)`。

## 9. UI 文案

推荐的英文字符串：

1. `account.cloudWords`：`Cloud words`
2. `account.cloudWordsThisMonth`：`Cloud words this month`
3. `account.cloudWordsUsage`：`{{used}} / {{limit}} words`
4. `account.cloudWordsReset`：`Resets {{date}}`
5. `account.lifetimeLicense`：`Lifetime license`
6. `account.byokUnlimited`：`BYOK usage is unlimited and does not count toward cloud words.`
7. `account.cloudQuotaWarning`：`You have used 90% of your monthly cloud words.`
8. `errors.cloud_quota_exceeded`：`Cloud words used up. Switch to BYOK or wait until your monthly reset.`
9. `settings.cloudLlmActive`：`Cloud AI is active for your plan.`
10. `settings.cloudSttActive`：`Cloud speech recognition is active for your plan.`

在面向 AppSumo 的界面中避免这些：

1. `5M tokens`
2. `10 hours`
3. `Gemini`
4. `Groq`
5. `OpenRouter`

## 11. 成功指标

主要指标：

1. AppSumo 激活率：兑换的买家在 24 小时内登录桌面 app 并完成一次成功云听写的百分比。

次要指标：

1. 云配额困惑：更少提及 “tokens”、“hours” 或 “what is my limit” 的工单。
2. BYOK 恢复：超额用户切换到 BYOK 而非流失的百分比。
3. 云请求成功率：排除用户取消与配额/鉴权错误后，STT 与 LLM 成功率保持在 98% 以上。
4. 语音到润色文本的中位延迟保持与当前云路径有竞争力。

护栏指标：

1. 每个活跃买家的 AppSumo 云 COGS。
2. 每个买家第 95 百分位月度云用量。
3. 配额绕过或竞态条件事件。
4. 退款/拒付率。

## 12. 风险与缓解

| 风险 | 影响 | 缓解 |
| ------------------------------------------ | ------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 用户与无限的 Letterly 比较 | OpenTypeless 可能显得有上限 | 把 BYOK 定位为无限且隐私友好；把托管云定位为公平的每月包含用量。 |
