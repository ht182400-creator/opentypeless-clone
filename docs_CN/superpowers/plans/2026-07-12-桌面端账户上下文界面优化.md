# 桌面端账户与上下文界面优化实施计划

> **面向智能体执行者：** 必需子技能：建议使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 来逐任务实现本计划。步骤使用复选框（`- [ ]`）语法进行跟踪。

**目标：** 用紧凑的弹窗替换内联的修改密码表单，并在上下文适配（context adaptation）旁边展示有代表性的已支持应用 logo。

**架构：** 把修改密码的呈现逻辑抽取到一个聚焦的 `PasswordDialog`，它接收凭证能力并委托现有的异步 mutation 回调。新增一个静态、不可交互的 `ContextAdaptationApps` 组件，由现有的本地资源支撑；`LlmPane` 负责放置位置，而应用注册表仍是行为的唯一事实来源。

**技术栈：** React 19、TypeScript、Tailwind CSS、react-i18next、Vitest、Testing Library，以及现有的 `AppLogo` 与桌面端弹窗模式。

## 全局约束

- 保留现有的 Account 与 Settings 路由及导航。
- 仅使用现有设计 token、10px 或更小的卡片 / 弹窗圆角，以及本地 WebP 应用图标。
- 密码弹窗最大宽度 380px，必须支持 Esc 关闭、点击遮罩关闭、打开时聚焦、以及忙碌状态下禁止关闭。
- 精确展示 Gmail、Slack、Lark、WeChat、Google Docs、Notion、GitHub、Cursor，其后跟 `+63`。
- logo 行不可交互，使用 16px 图标，带有应用名的无障碍标签 / 提示，并在 AI 润色（AI polish）禁用上下文适配时变暗。
- 不要改动密码 API、鉴权状态语义、应用检测、提示词组装或云端契约。
