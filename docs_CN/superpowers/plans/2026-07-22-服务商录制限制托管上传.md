# 服务商录制限制与托管上传实施计划

> **面向智能体执行者：** 必需子技能：使用 superpowers:executing-plans 来逐任务实现本计划。步骤使用复选框（`- [ ]`）语法进行跟踪。

**目标：** 通过 Rust 端强制实施“感知服务商”的录制限制来解决 Issue #81，并让 TalkMore Cloud 录音最长可达十分钟，同时不越过 Vercel Pro 的 4.5 MB 请求边界，也不劣化普通短录音的延迟。

**架构：** Rust 持有一个带版本号的 provider 能力注册表、配置迁移，以及权威的单调录制截止时间。前端渲染解析后的能力与用户选择，但不能延展 Rust 的截止时间。TalkMore 先发布一个 version-2 托管音频能力与严格的 WAV/Ogg-Opus 容器校验器。桌面端随后仅在托管的 Cloud 路径上新增一个静态捆绑的 Opus 编码器，在 3.5 MB 以下保持与今天完全一致的 WAV 行为，并在服务端能力缺失或过期时保守回退到 30 秒。

**技术栈：** Rust 2021、Tauri 2、CPAL、Tokio、`opusic-c 1.6.1`、`ogg 0.9.2`、React、TypeScript、Next.js、Vitest。

## 全局约束

- 在启用桌面端能力 version 2 之前，先在隔离的 cloud-usage worktree/分支完成并部署 TalkMore 解析器/能力路由；保留旧桌面端兼容性。
- Direct/BYOK 与流式 provider 的音频路径不得被转码。
- 在或低于 3,500,000 WAV 字节的短托管录音，必须发送与今天相同的 WAV 字节。
- Ogg/Opus 工作绝不在 CPAL 回调或 WebView 中运行，且不需要终端用户安装系统编解码器。
- Rust 在 Windows、macOS、Linux 上是截止时间的权威，WebView 计时器仅用于展示。
- 到达限制时优雅地 finalize 并精确提交一次已录音频。
- 缺失、过期、禁用或不兼容的托管能力元数据，回退到历史的 30 秒 Cloud 行为。
- 绝不向 TalkMore 发送超过 4,200,000 字节的 multipart body、超过 4,000,000 字节的音频部分，或超过 600 秒的录音。
