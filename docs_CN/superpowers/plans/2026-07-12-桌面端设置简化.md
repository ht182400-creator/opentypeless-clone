# 桌面端设置简化实现计划

> **面向 agent 执行者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务逐条实现本计划。步骤使用复选框（`- [ ]`）语法跟踪。

**目标：** 在保留所有 P0/P1 行为的同时降低默认设置的密度，让场景成为应用族写作模式可见且可配置的地方，并关闭两个打包桌面端的无障碍/状态缺口。

**架构：** 保留现有的面板与 store。通过渐进式展开简化每个组件，复用持久化的 `family_scene_assignments` 做应用族场景选择，把精确 app 映射保留为用户拥有的覆盖，并只新增最小的持久化 `system_scene_overrides` 配置字段，而不是第二个映射存储。每次生产改动前，用聚焦的 Vitest 测试冻结组件行为。

**技术栈：** React 19、TypeScript 5.8、Tailwind CSS 4、react-i18next、Zustand、Tauri 2、Vitest 4、Testing Library、既有的 Lucide 与 dialog/menu 模式。

## 全局约束

- 已批准的来源：`docs/superpowers/specs/2026-07-12-desktop-settings-simplification-design.md`。
- 保留设置路由、六个面板目标、当前设计 token 与 ≤10px 圆角。
- 保留密码 API、账户语义、云/配额行为、应用检测、prompt 组合、意图路由、快捷键持久化、翻译持久化、词典事务与备份隐私。
- 不要新增 71-app 设置陈列馆，也不要持久化原始进程、bundle、可执行、host、标题、URL、页面、听写或选中文本素材。
- 在场景中暴露受支持的应用族写作模式，带代表性应用 logo 与紧凑场景选择器。
- 让精确 app 覆盖的创建只能从安全的检测上下文或既有用户映射到达。
- 仅使用现有的本地应用标记与 Lucide 图标。
- 每个新增加的仅图标动作都有无障碍名称与 tooltip。
- 使用 TDD：每个生产行为变更都跟随一个聚焦的失败测试。
- 不要修改或暂存无关的 `docs/growth/` 或 `docs/images/` 文件。
