# 自定义本地 STT 设计

日期：2026-06-01

## 概述

为 OpenTypeless 增加对“本地 / 自定义”STT 的一等公民支持，目标接口与 OpenAI 兼容的转写服务。直接驱动力来自 GitHub Discussion #41：有用户在内网 GPU 上自建了 Speaches，希望 OpenTypeless 调用其 `/v1/audio/transcriptions` 接口，而不是当前写死的 Whisper 兼容端点。

该功能应在不把这个 MVP 变成完整模型管理器的前提下，让本地 STT 易于上手。已经运行 Speaches、LocalAI 或其他 OpenAI 兼容 Whisper 服务的用户，可以选择一个预设、按需调整 Base URL / 模型、测试连接，并复用现有的录音管线。

## 目标

- 新增一个标记为 “Local / Custom Whisper”（或等价表述）的 STT provider。
- 通过复用现有的 `WhisperCompatProvider` 支持 OpenAI 兼容的 `audio/transcriptions` 接口。
- 允许用户配置：
  - 预设：Speaches 或自定义（OpenAI 兼容）。
  - Base URL，例如 `http://localhost:8000/v1`。
  - 模型名。
  - 可选的 API key。
- 对于没有鉴权的本地服务，API key 应设为可选。
- 提供友好的测试流程，对常见配置问题给出可操作的错误提示。
- 保留所有现有 STT provider 及其当前默认值。
- 配置继续保存在现有的 Tauri store 中（本地）。

## 非目标

- 不下载 Whisper 模型。
- 不启动、停止、安装或更新本地 STT 服务。
- 不管理 GPU / CPU 运行时的选择。
- 不新增自定义请求结构编辑、任意 multipart 字段或响应映射。
- 不新增流式本地 STT。本方案使用现有的“文件上传 → 最终转写”路径。
- 暂不构建更通用的插件系统。

## 用户体验

在 Settings -> Speech Recognition（语音识别）中，用户可以选择一个新的 provider：“Local / Custom Whisper”。

选中后，面板显示：

- 预设选择器：
  - Speaches
  - Custom OpenAI-compatible（自定义 OpenAI 兼容）
- Base URL 输入框。
- Model 输入框。
- 可选的 API Key 输入框。
- 现有的 Language（语言）选择器。
- 现有的 Test（测试）按钮。

选择 Speaches 预设会填入：

- Base URL：`http://localhost:8000/v1`
- Model：一个合理的默认值，例如 `Systran/faster-whisper-large-v3`

选择 Custom OpenAI-compatible（自定义）时，各字段保持可编辑，不假定特定端口。占位符应展示期望的格式：`http://localhost:8000/v1`。

产品立场是“帮用户搭好本地环境，而不是托管本地运行时”。UI 应避免暗示 OpenTypeless 会下载模型或启动服务（本 MVP 阶段）。可以提示：本地服务必须已经处于运行状态。

## URL 处理

面向用户的字段是 base URL，而不是完整端点。建议输入：

```text
http://localhost:8000/v1
```

后端通过追加 `/audio/transcriptions` 得到最终的转写端点。

为了健壮性，也要接受用户粘贴了完整端点的情况：

```text
http://localhost:8000/v1/audio/transcriptions
```

应将其归一化为同一个最终端点，而不是把路径再追加一次。这样表单更宽容，又不需要在 UI 里暴露端点路径的复杂性。

## 配置模型

扩展应用配置，新增自定义 STT 字段：

- `stt_custom_preset`：字符串，默认 `speaches`
- `stt_custom_base_url`：字符串，默认 `http://localhost:8000/v1`
- `stt_custom_model`：字符串，默认 `Systran/faster-whisper-large-v3`

当所选 provider 是 Local / Custom Whisper 时，复用现有的 `stt_api_key` 字段作为可选 API key。这样避免新增第二个密钥字段，也与现有 STT 设置行为一致。

前端 provider id 应保持稳定，例如：

```text
custom-whisper
```

Rust 端应把这个 provider 当作 Whisper 兼容 provider 处理，但其 endpoint 和 model 来自已保存的 AppConfig，而不是 `stt::config::get_whisper_config`。

## 后端设计

当前状态：

- `src-tauri/src/stt/config.rs` 为 Whisper 兼容 provider 返回写死的 endpoint / model 对。
- `src-tauri/src/stt/whisper_compat.rs` 已实现 OpenAI 兼容的 multipart 上传路径。
- `src-tauri/src/stt/mod.rs` 为 `get_whisper_config` 处理的 provider 名创建 `WhisperCompatProvider`。
- `src-tauri/src/commands/stt.rs` 重复了 Whisper 兼容 provider 的连接测试逻辑。

设计：

1. 新增一个小巧的配置构造器，能从以下两种来源之一产出 `WhisperCompatConfig`：
   - 已知的 provider id（如 `groq-whisper`），或
   - 存放在 `AppConfig` 中的自定义 provider 字段。
2. 用一个 Rust 辅助函数统一归一化自定义 base URL：
   - 去除首尾空白。
   - 去除结尾斜杠。
   - 如果 URL 以 `/audio/transcriptions` 结尾，则原样使用。
   - 否则追加 `/audio/transcriptions`。
3. 更新管线 provider 的创建逻辑，使 `custom-whisper` 使用自定义 endpoint / model。
4. 更新 STT 的 test 与 benchmark 命令，使其能用相同的自定义字段测试 `custom-whisper`。

当 `custom-whisper` 配置无效时，后端不应静默回退到 `glm-asr`，而应返回清晰配置错误。

## 前端设计

更新 STT 设置面板：

- 把 `custom-whisper` 加入 `STT_PROVIDERS`。
- 当所选 provider 是 `custom-whisper` 时，渲染 preset、base URL、model、可选 API key 以及 Test。
- 当 preset 切换为 Speaches 时，填入 Speaches 默认值。
- 当 preset 切换为 Custom 时，保留当前值，避免用户已编辑内容丢失。
- 语言字段保持可见，因为现有 Whisper 兼容请求可以传递语言提示。

组件应与当前 Settings 风格保持一致：

- 使用现有的 `FormField`。
- 使用现有的按钮 / 测试状态模式。
- 使用 i18n key，而不是写死的可见字符串。
- 除非当前设置布局本就需要，否则不要新增单独的说明卡片。

## 错误处理

Test 操作应把后端失败翻译成可操作的提示。建议映射：

- 网络 / 连接超时：“Local STT server is not reachable. Check that it is running and the port is correct.”（本地 STT 服务不可达，请检查它是否在运行、端口是否正确）
- 401 或 403：“This server requires an API key.”（该服务需要 API key）
- 404：“The Base URL does not look OpenAI-compatible. Use a base URL like `http://localhost:8000/v1`.”（Base URL 看起来不是 OpenAI 兼容的，请使用类似 `http://localhost:8000/v1` 的 base URL）
- 400：“The server rejected the request. Check the model name and server logs.”（服务拒绝了请求，请检查模型名和服务日志）
- 模型为空：“Model is required for Local / Custom Whisper.”（Local / Custom Whisper 必须填写模型）
- Base URL 为空：“Base URL is required for Local / Custom Whisper.”（Local / Custom Whisper 必须填写 Base URL）
- URL 协议非法：“Base URL must start with `http://` or `https://`.”（Base URL 必须以 `http://` 或 `https://` 开头）

连接测试仍应发送现有的“短静音 WAV”请求。结果是空文本也可以接受，只要 HTTP 响应成功即可。

## 数据流

```text
Settings（设置）
  -> AppConfig 保存 provider、可选 API key、自定义 base URL、自定义 model
  -> Pipeline 加载 AppConfig
  -> 创建自定义 WhisperCompatConfig
  -> WhisperCompatProvider 把 WAV 上传到归一化后的端点
  -> 原始转写文本进入现有的 LLM 润色 / 输出 / 历史流程
```

## 测试

前端测试：

- STT provider 列表包含 Local / Custom Whisper。
- 选择自定义 provider 时显示 preset、base URL、model、API key 与 Test。
- Speaches 预设会填入默认 base URL 与 model。
- Custom 预设会保留用户输入的值。
- 只要 base URL 与 model 存在（即使 API key 为空），Test 按钮就可点击。

Rust 测试：

- Base URL 归一化会追加 `/audio/transcriptions`。
- 接受完整端点输入，且不重复路径。
- 为空或非法的 base URL 返回配置错误。
- `custom-whisper` 不会回退到 `glm-asr`。
- `custom-whisper` 的 `WhisperCompatConfig` 使用配置中的 endpoint / model。

集成 / 手动验证：

- 现有 provider 仍能运行它们当前的配置测试。
- 自定义 provider 能在无 API key 的情况下调用本地 OpenAI 兼容端点。
- 自定义 provider 能调用需要 Bearer token 的端点。
- 本地服务失败时给出用户友好的错误。

## 未来工作

本 MVP 有意给更大的“Managed Local STT（托管的本地 STT）”功能留出空间：

- 下载并缓存 Whisper / faster-whisper 模型。
- 启动并监控内置或 sidecar 的本地 STT 服务。
- 提供模型尺寸选择，如 tiny / base / small / medium / large。
- 检测可用的 CPU / GPU 加速。
- 展示磁盘占用并支持模型移除。

该功能应单独设计，因为它会把 OpenTypeless 从“本地 STT 服务的客户端”变成“运行时管理器”。
