# 问题 #81/#83、STT 录制限制与云端用量效率设计

- 日期：2026-07-22
- 状态：TalkMore 兼容服务已部署到生产环境，能力版本 2 处于禁用状态；桌面端/跨平台推广待定；原子化配额切换延后
- 仓库：`opentypeless` 桌面端与 `talkmore` 云服务
- 问题：[OpenTypeless #81](https://github.com/tover0314-w/opentypeless/issues/81)、[OpenTypeless #83](https://github.com/tover0314-w/opentypeless/issues/83)

## 1. 摘要

本设计在不牺牲当前桌面体验的前提下解决三个相关问题：

1. 问题 #83：用户首次录音的开头，在麦克风与 STT provider 初始化期间可能丢失。
2. 问题 #81：桌面端对所有 STT provider 套用单一的全局 30 秒录制限制，但各 provider 的约束并不相同。
3. TalkMore 云端用量：桌面端每五分钟轮询一次订阅状态，造成不必要的 Neon 数据库活动，并可能妨碍计算资源缩减到零。

批准的方向是：

- 同时启动麦克风采集与 STT 连接，且不在平台音频流真正开始运行之前报告录音就绪；
- 用 Rust 持有的 provider 能力解析器，以及 `Auto（推荐）` 或用户自定义设置，替换全局 30 秒规则；
- 通过混合托管上传路径将 TalkMore 云端产品限制设为 10 分钟：短录音保留 WAV，长录音使用有界的 Ogg/Opus；
- 用仅在有意义的产品事件上去重刷新的方式，替换固定的订阅轮询；本期发布中，在托管输出送达后再刷新一次状态，而不是改变计费响应契约；
- 把 Neon 缩减到零的唤醒延迟藏到活跃的云端录音时间内，而不是在桌面空闲时让 Neon 保持唤醒；
- 把 Neon 与现有生产配额实现作为本期计费的权威来源；
- 延后原子化/幂等配额重写，直到刻意引入隔离的真实 PostgreSQL 测试环境；
- 先部署服务端变更，再部署桌面端变更，并为现有客户端保留向后兼容的响应字段；
- 在关闭问题前，要求 Windows、macOS、Linux 三端的运行时验证。

桌面端在 TalkMore 或 Neon 处于冷启动、缓慢或临时不可用时，必须保持可用。缓存的账户数据仅用于展示；所有托管云端的授权与配额决策仍由服务端决定。

## 2. 当前证据

### 2.1 问题 #81

当前桌面端配置存储一个 `max_recording_seconds` 值，默认为 30 秒。`src/components/Capsule/DurationTimer.tsx` 使用 WebView 定时器，在到达该值时调用 `stop_recording`。

这带来两个问题：

- 30 秒对 GLM-ASR 是真实限制，但对 Groq、OpenAI 兼容上传 provider、流式 provider 或 TalkMore 云端并非通用限制；
- 前端定时器在窗口被隐藏、节流，或被 Windows WebView2、macOS WKWebView、Linux WebKitGTK 以不同方式挂起时，并不可靠。

当前的文件上传 provider 缓冲 16 kHz、16 位、单声道 PCM，并在录音结束时构建 WAV 文件。`src-tauri/src/stt/whisper_compat.rs` 与 `src-tauri/src/stt/cloud.rs` 都使用 24 MiB 的音频安全缓冲区。这个客户端约束与上游 provider 公布的限额同样重要。

### 2.2 问题 #83

问题 #83 出现的原因是：在平台音频采集与 STT 连接仍在准备就绪的过程中，UI 就可能进入录音状态。固定的平台延迟并不可靠，并且会拖慢每一次录音。

已提交的行为锁定在当前桌面特性分支上：

- 音频采集有 `Starting`、`Recording`、`Idle` 三种状态；
- 仅在 CPAL `stream.play()` 成功后，采集才报告就绪；
- 音频初始化与 STT 连接并发等待；
- 音频通道在 provider 连接期间缓冲最多 60 秒、每帧 20 ms 的数据块；
- 听写与 Ask 录音使用相同的启动屏障。

本规范不将这些改动视为已发布。它们仍需要评审、已提交的测试，以及在所有三个受支持操作系统家族上的真实设备验证。

### 2.3 TalkMore 与 Neon

生产版 TalkMore 项目运行在 Vercel Pro 上。这移除了设计 210 秒函数时长要求中计划层面的阻碍：Vercel 文档说明，在不启用 Fluid Compute 时 Pro 至少 300 秒，启用 Fluid Compute 时最多 800 秒。STT 路由仍必须显式声明并校验其时长，而非依赖项目默认值。

Vercel Pro 并未提高 4.5 MB 的函数请求体限制。即使执行时长预算可用，混合托管上传设计仍属必要。

桌面端当前：

- 在主 WebView 中初始化鉴权；
- 当用户登录时，每五分钟刷新一次 `/api/subscription/status`；
- 还会在获得焦点时刷新，但有 30 秒节流；
- 在隐藏的 Ask WebView 中再次初始化相同的 auth store。

主 WebView 在应用隐藏到托盘时仍保持存活。因此，一个空闲的已登录桌面端每小时大约产生 12 次状态请求，每天约 288 次。

TalkMore 状态路由当前执行鉴权、有效权益查询以及 `getOrCreateQuota`。权益查询通过多个查询读取订阅与许可状态，而 `getOrCreateQuota` 可能在一次 GET 请求中写入。

只读的生产环境检查发现了数据库很小，但累积语句活动极高。尤其是一张七行的 AppSumo 许可表出现了超过一百万次顺序扫描。对七行做顺序扫描本身并不昂贵；证据指向的是请求频率与往返次数过多，而非表大小。

当前的云端配额流程在 reserve、settle、release 时还会发出若干条语句。遗留配额代码使用内存条目，但在请求后显式刷新，去掉了大部分批处理收益。

Neon 中不存储任何音频负载。主要优化目标是计算活动与数据库往返次数，而非存储量。

## 3. 目标

### 3.1 录制与 Provider 目标

1. 一旦用户开始录音，就捕获首个语音音频，包括冷启动的首次使用。
2. 让显示并强制执行的录制限制匹配所选 STT provider 与当前传输方式。
3. 给用户一个可见的 `Auto（推荐）` 选项，以及安全的自定义时长选项。
4. 将 TalkMore 云端录音控制在 10 分钟或以内，同时为普通短录音保留当前 WAV 路径。
5. 在达到限制时优雅停止并提交已录音频，而非丢弃它。
6. 按住说话、切换录音、听写与 Ask 录音使用相同的行为。
7. 让限制强制与 WebView 可见性及定时器节流无关。
8. 让一次 10 分钟的托管上传在部署的 Vercel 函数请求体限制之下完成，且无需临时对象存储。

### 3.2 云端与成本目标

1. 为升级过的客户端移除五分钟的桌面端订阅轮询循环。
2. 让一个空闲的已登录应用停止产生 TalkMore 数据库流量。
3. 在成功的托管云端 STT、LLM 或 Ask 调用后，立即显示配额变更。
4. 在降低读取频率与状态路由往返次数的同时，保留当前的生产权益与配额行为。
5. 将 `/api/subscription/status` 的业务数据工作量降为鉴权后的一次只读数据库往返。
6. 把每次配额状态转换降为一条原子业务数据语句或事务往返，视为需要真实 PostgreSQL 并发证据的独立未来里程碑。
7. 避免 Redis、个性化 CDN 缓存，以及在空闲时唤醒 Neon 的 cron 任务。
8. 仅为真实的账户活动或正在进行的托管云端操作唤醒 Neon，并将该唤醒与用户正在说话的时间重叠。

### 3.3 用户体验目标

1. 绝不因 TalkMore 状态刷新而阻塞本地应用外壳或 BYOK 录音。
2. 绝不因 Neon 冷启动或网络离线，就把返回的付费用户临时显示为 Free。
3. 在用量同步较晚失败时，保留流式文本延迟与已送达内容。
4. 及时反映购买与许可激活，包括在支付 webhook 延迟时。
5. 避免主窗口、胶囊与 Ask 窗口之间出现重复警告或不一致的配额显示。
6. 在整个推广过程中保持当前客户端兼容。
7. 不劣化常见的短录音停止到转写延迟、转写质量、采集可靠性，或电池/CPU 行为。

## 4. 非目标

- 不在本工作中加入 FLAC 编码、音频分块、可续传上传、临时对象存储交接，或超过已批准 provider/产品上限的录音。
- 不在本工作中转码 BYOK 或直接 provider 上传。Ogg/Opus 仅限于 TalkMore 托管云端传输。
- 不在用量记账中将音频或转写存入 Neon。
- 不引入 Redis、WebSocket 权益服务，或新的常驻 worker。
- 不改变套餐价格、月度配额数量、AppSumo 档位，或计费词数的定义。
- 不重新设计整个 Settings、Account、Capsule 或 Ask UI。
- 不把 Vercel 进程本地缓存作为订阅或配额的权威来源。
- 不强制升级旧桌面客户端以仅获取计算节省。
- 不在发布与跨平台运行时验证前宣称问题 #81 或 #83 已关闭。
- 不在当前发布中引入项目测试数据库要求，或将生产计费切换到分阶段原子配额 schema。

### 4.1 当前计费范围决策

所有者不计划在现阶段引入隔离的数据库测试环境。因此：

- 原子 reserve、settle、release、replay、reconciliation 仍设计为保留，但不在当前发布范围；
- 附加的原子用量 schema 与迁移产物必须从当前发布中排除；否则遗留 Drizzle `select()` 与 `returning()` 调用即便新路由不直接使用这些字段，也可能隐式引用未应用的列；
- 现有生产配额变更与计费公式保持不变；
- 单元测试与契约测试可覆盖兼容性，但不得表现为 PostgreSQL 并发正确性的证明；
- 原子配额切换只能在有隔离的真实 PostgreSQL 端点可用于破坏性、并发、replay 测试时恢复；
- 此延后不阻塞问题 #81/#83、provider 感知的录制限制、托管 Ogg/Opus 上传、空闲轮询移除，或单读账户状态优化。

## 5. 产品决策

### 5.1 录制设置

该设置有两种模式：

- `Auto（推荐）`：使用当前 provider 的推荐最大值；
- `Custom`：使用用户选择的值，且不大于 provider/客户端的硬上限。

Settings UI 在 Auto 旁显示解析出的值，例如：

- Groq 显示 `Auto（推荐）— 10 分钟`；
- GLM-ASR 显示 `Auto（推荐）— 30 秒`；
- Apple Speech 显示 `Auto（推荐）— 1 分钟`。

自定义选项包含 30 秒、1 分钟、2 分钟、5 分钟、10 分钟、30 分钟、60 分钟以及自定义数值输入中的适用值。高于解析硬上限的值不可选。自定义字段必须说明允许范围，并在解释修正后钳制无效的持久化值。

### 5.3 托管云端编码边界

直接/BYOK 文件上传 provider 继续使用当前的 16 kHz、16 位、单声道 PCM/WAV 路径。TalkMore 云端使用混合传输，因为部署的 Next.js API 作为 Vercel 函数运行，其请求体有不可配置的 4.5 MB 负载限制。路由当前的 25 MiB 应用常量无法扩展该平台限制；超大请求在路由代码运行前就被拒绝。

近似 WAV 负载大小为：

```text
字节数 = 秒数 * 16,000 采样/s * 2 字节/采样 + 44 字节头
```

- 600 秒约为 19,200,044 字节，无法通过当前 Vercel 路由；
- 720 秒约为 23,040,044 字节；
- 当前 24 MiB 客户端缓冲为 25,165,824 字节。

托管云端因此按音频部分的字节大小选择其负载：

- 当 WAV 音频部分最多 `3,500,000` 字节时，原样发送当前 WAV；
- 超过该阈值时，以恒定 48 kbit/s 的单声道语音发送 Ogg/Opus 编码，并设 10 分钟时长上限；
- 将编码音频部分限制在 `4,000,000` 字节，完整 multipart 请求限制在 `4,200,000` 字节，在 Vercel 4.5 MB 平台边界下留出显式余量；
- 600 秒、48 kbit/s 负载在小的 Ogg 开销之前约为 3,600,000 字节，在使用恒定比特率与正常页聚合时仍低于编码文件上限；
- 绝不仅从文件名或 MIME 字符串选择编码；服务端校验容器与时长。

这不是「压缩一切」。常见的短录音保留 WAV 当前的延迟与无损信号。只有无法作为 WAV 安全穿越托管路由的录音才使用 Opus。Groq 接受 Ogg 上传，而直接/BYOK 上传 provider 保留其现有路径与限制。

桌面端必须在 Windows、macOS、Linux 上使用一个固定的、打包的 Opus 实现。它不得依赖 ffmpeg、GStreamer、AVFoundation、Media Foundation，或系统安装的 `libopus`。

实现评审选定：

- `opusic-c = 1.6.1` 配合其默认 `bundled` 特性，解析 `opusic-sys = 0.7.3` 并静态构建 vendored 的 Opus 1.6.1 源码；
- `ogg = 0.9.2` 用于纯 Rust 的 Ogg 包/页写入与读取；
- 构建/CI 机器需 Rust 1.82 或更新，以及 CMake 3.16 或更新；最终用户机器收到静态链接的编解码器，无需安装编解码器；
- 在随附的 `THIRD_PARTY_NOTICES.md` 中为 `opusic-c`、`opusic-sys`、vendored Opus 源码与 `ogg` 提供 BSD-3-Clause 声明；
- 在启用能力版本 2 之前，为 `x86_64-pc-windows-msvc`、`aarch64-apple-darwin`、`x86_64-apple-darwin`、`x86_64-unknown-linux-gnu` 构建 CI 与发布产物。

TalkMore 用 `src/lib/audio-container.ts` 中一个聚焦的 TypeScript 容器解析器校验 WAV 与 Ogg/Opus。它不安装 ffmpeg 或服务端原生编解码器包：该解析器遍历 RIFF 块或 Ogg 页，校验页结构与 CRC，从 TOC 数据重建 Opus 包，推导包时长，并在配额预留前检查 granule/pre-skip 一致性。

12 分钟的直接上传 provider 硬上限继续在现有 24 MiB PCM 客户端缓冲下留出余量。那些 provider 的压缩与分块仍延后。

设计时的平台参考：

- Vercel 函数请求体限制：<https://vercel.com/docs/functions/limitations>
- Vercel 函数按套餐与 Fluid Compute 设置的时长限制：<https://vercel.com/docs/functions/limitations#max-duration>
- Vercel 大上传指引：<https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions>
- Groq 接受的格式与文件限制：<https://console.groq.com/docs/speech-to-text>

### 5.4 已考虑的托管上传替代方案

选定的混合路径优于以下替代方案：

- **压缩每次托管录音：** 选择逻辑更简单，但它在占用量主体的短录音上也消耗 CPU 并引入有损输入，而它们本就放得下。这与「不劣化」目标冲突。
- **上传 WAV 到临时对象存储并给 Groq 一个签名 URL：** 保留无损音频并绕过 Vercel 的 body 限制，但增加了上传/令牌/存储生命周期，临时持久化用户音频，并可能新增一次网络跳转。它仍是未来的回退方案，而非主路径。
- **在 Vercel 外运营专用媒体代理：** 保留当前 WAV 客户端，但增加了常驻基础设施、区域路由、安全、可观测性与与问题规模不相称的运维成本。
- **将 TalkMore 云端限制在约 109 秒：** 所需工程最少，但无法满足已批准的 10 分钟托管云端产品行为。

## 6. 桌面端录制架构

### 6.1 Provider 能力注册表

Rust 持有一个注册表，并向前端暴露解析出的能力。TypeScript 不得维护重复的 provider 限制表。

概念模型：

```rust
enum SttTransport {
    FileUpload,
    Streaming,
    LocalBuffered,
    ManagedUpload,
}

enum RecordingLimitSource {
    Provider,
    ManagedProduct,
    ClientBuffer,
    ProductSafety,
    UnknownUpstream,
}

struct SttRecordingCapability {
    provider_id: String,
    transport: SttTransport,
    recommended_max_seconds: u32,
    hard_max_seconds: u32,
    max_upload_bytes: Option<u64>,
    source: RecordingLimitSource,
    explanation_key: String,
}
```

解析器返回原始能力以及当前配置的 `effective_max_seconds`。

```text
有效最大值 = min(
  模式选择的时长,
  provider 硬上限,
  客户端传输安全上限,
  适用时的托管服务端最大值
)
```

对于 TalkMore 云端，桌面端有内置的 600 秒产品上限，但不把该上限视为部署服务端支持版本 2 传输的证明。它取本地策略与协商出的服务端格式/时长/字节策略中的较小值。缺失或不兼容的能力元数据解析回历史的 30 秒云端回退；服务端响应可能收窄，但绝不扩展本地产品上限。

### 6.2 配置兼容与迁移

新增 `recording_limit_mode`（`auto` 或 `custom`）与 `custom_recording_limit_seconds`。保留现有 `max_recording_seconds` 作为解析有效值的兼容镜像，而非用户意图的新来源。Rust 在 provider、模式、服务端能力或自定义时长被持久化时重新计算该镜像。因此较旧的桌面端会为上次保存配置时所选的 provider 收到一个安全值。

对没有 `recording_limit_mode` 的配置的加载规则：

- `max_recording_seconds == 30`：迁移到 `auto`，并带 600 秒自定义回退，因为 30 秒是历史默认值；
- 任何其他有效值：迁移到 `custom` 并复制到 `custom_recording_limit_seconds`，清楚保留用户改过它的证据；
- 零或无效值：迁移到 `auto`，并将自定义回退设为 600 秒。

新安装存储 `recording_limit_mode = auto`、`custom_recording_limit_seconds = 600`，以及为默认 provider 解析出的 `max_recording_seconds` 兼容镜像。

当自定义值超过新选 provider 的上限时：

- 不要在用户录音时静默持久化破坏性替换；
- 在 provider 选择或 Settings 加载时，提示之前的值对该 provider 不可用；
- 立即为安全钳制有效值；
- 仅当用户保存设置时，才持久化钳制后的自定义值。

降级到不认识新字段的版本，仍会看到一个安全的、由 provider 解析出的 `max_recording_seconds`。如果该旧版本更改 provider，在再次升级之前可能保守地保持上限，但它不能扩展到最后一次安全镜像之上。重新升级后，除非旧版本替换了配置，否则新字段恢复为用户意图来源；若旧版本替换了配置，则迁移规则再次运行。

### 6.3 权威截止时间

Rust 持有录制截止时间。`DurationTimer` 显示已用时与剩余时间，但不是唯一能停止录音的组件。

权威开始时间是 CPAL `stream.play()` 成功的瞬间，而非 STT 连接也就绪的稍后瞬间。采集就绪信号因此携带或记录该单调瞬间。这防止 provider 连接时间延长 30 秒或 10 分钟限制。

在音频采集开始时，Rust 快照：

- provider id 与传输；
- 解析出的能力；
- 所选限制模式；
- 有效最大值；
- 单调开始时间与截止时间；
- 一个录音会话 id。

规则：

- provider/配置变更不改变进行中的录音；唯一的例外是更新后的鉴权托管服务端能力收窄了传输安全，它可能只缩短活跃的云端截止时间；
- 来自上一会话的陈旧定时器无法停止更新的会话；
- 截止时间在管线仍处于 `Preparing` 时继续运行，慢 STT 启动期间的过期在启动所有权建立后立即成为一次延后的/优雅的停止；
- 到达截止时间执行与手动停止相同的优雅停止/收尾路径；
- 现有的音频缓冲保护仍作为第二安全层；
- 如果先到达安全保护，管线停止并提交缓冲音频，而非返回丢弃录音的错误；
- 系统睡眠后，过期的单调截止时间在进程恢复时恰好触发一次停止；
- 前端可在显示的截止时间请求停止作为响应性优化，但重复的停止请求必须幂等。

用户通知：

- 对于至少五分钟的限制，在剩余 60 秒与 10 秒时通知；
- 对于低于五分钟的每个受支持限制，在剩余 10 秒时通知一次；
- 自动停止时，标识来源，例如 `Reached the Groq recording limit (10 minutes)` 或 `GLM-ASR supports recordings up to 30 seconds`；
- 收尾成功时，自动停止不呈现为错误。

### 6.4 托管云端负载构建器

只有 `CloudSttProvider` 创建额外的 Ogg 负载。该 provider 继续保留当前管线所需的 16 kHz 单声道 PCM，并从相同的有序数据块供给一个专用编码器 worker。编码绝不能在 CPAL 回调、WebView 线程，或作为 Tauri 异步执行器线程上的阻塞工作运行。

编码器使用 20 ms 帧、恒定 48 kbit/s 单声道语音配置，以及内存中的 Ogg 容器。复用器将包聚合到正常的 Ogg 页，而非每 20 ms 包刷新一页，因为每包页开销会消耗 Vercel 安全余量。provider 与编码器之间的队列是有界的。每次录音拥有自己的编码器、负载状态、采样计数与取消令牌；不允许进程全局编码器或跨录音缓冲。

停止时：

1. 从捕获的采样计数推导时长，而非挂钟时间或压缩字节；
2. 如果生成的 WAV 音频部分最多 `3,500,000` 字节，丢弃未使用的编码负载并发送 WAV；
3. 否则收尾 Ogg/Opus，并在创建 multipart 数据前校验编码文件上限与托管的 600 秒上限；
4. 从负载字节与时长选择自适应请求超时，不改变 60 秒或更短录音的当前 60 秒超时；
5. 成功后、终态错误后或取消后，清除 PCM 与编码缓冲。

长请求超时是：

```text
timeoutSeconds = if durationSeconds <= 60 {
  60
} else {
  clamp(60 + ceil(payloadBytes / 32,000), 60, 180)
}
```

这在非常慢的 256 kbit/s 上行链路上给 3.6 MB 负载约 173 秒，同时保留普通短上传当前的 60 秒行为。TalkMore 路由必须至少有 210 秒的已部署函数时长，在 180 秒客户端上限之外留出服务端清理/响应余量。Vercel Pro 无论是否启用 Fluid Compute 都支持该设置，但部署验证必须记录有效的路由时长，以及是否启用了 Fluid Compute。如果部署环境无法支撑该时长，则不得通告能力版本 2。连接/TLS 失败仍独立有界，重试策略通过现有的 operation/stage 键保持幂等。

失败规则：

- 编码器初始化失败不阻止录音；它立即将该会话的有效云端截止时间降低到 109 秒的 WAV 安全时长，并解释扩展云端格式不可用；
- 编码器队列溢出或录音中错误被记录为编码器失败，绝不静默丢弃音频帧；
- 在 WAV 阈值以下，编码器失败仍正常提交 WAV；
- 在 WAV 阈值以上，provider 可在专用 worker 上从保留的 PCM 做一次有界重编码；如果这也失败，它返回稳定的可重试 `managed_audio_encode_failed` 错误，且不得发送超大的 WAV；
- 意外提前到达的编码字节上限执行一次优雅自动停止并提交有效的编码前缀；它不产生 Vercel 413，也不丢弃整个会话；
- 本地传输安全引起的自动停止在日志与用户文案中，都与 provider 的时长限制区分开。

编码器路径的发布门槛是：它必须能连续处理，而不会在代表性的低端 Windows、macOS、Linux 设备上导致现有 CPAL `try_send` 路径丢弃数据块。

### 6.5 托管云端服务端校验

TalkMore 不得仅信任桌面端定时器、文件名、MIME 类型或 `Content-Length`。

`/api/proxy/stt` 必须：

- 用 `4,000,000` 字节的音频部分上限替换误导性的 25 MiB 应用限制，并在到达应用代码时拒绝超过 `4,200,000` 字节的完整请求；
- 只接受校验过的 16 kHz 单声道 PCM WAV，以及包含单个有效单声道 Opus 逻辑流的 Ogg；
- 从 RIFF 块计算 WAV 时长；对于 Ogg/Opus，从 Opus TOC 数据累加校验过的包时长，并要求与单调 granule 位置与 pre-skip 一致，而非仅信任客户端提供的最后 granule；
- 在配额预留或 Groq 之前，拒绝零、畸形、截断、链接、多轨或不支持的音频；
- 以稳定代码 `audio_duration_exceeded` 拒绝实际时长超过 600 秒，并包含 `maxRecordingSeconds: 600`；
- 以稳定代码 `audio_payload_exceeded` 拒绝超大的音频部分，并包含 `maxUploadBytes: 4000000`；
- 将校验过的文件以其真实文件名与内容类型转发给 Groq，而非把每个负载都命名为 `audio.wav`；
- 使用服务端校验的时长为遗留双表与云端词套餐确定初始预留；当前固定的 30 秒估计对长上传不够；
- 配置并校验至少 210 秒的已部署函数时长，并在超时与重试间保留幂等的 reserve/release/settle 行为；
- 在预留配额或调用 Groq 之前执行字节、容器与时长校验。

状态/账户快照在不额外数据库查询的情况下通告一个静态的托管能力。通告由一个全局服务端部署标志控制，这样在移除解析器兼容性的同时，也能禁用长格式特性：

```json
{
  "managedSttCapabilities": {
    "version": 2,
    "maxRecordingSeconds": 600,
    "maxMultipartBytes": 4200000,
    "formats": [
      {
        "mimeType": "audio/wav",
        "maxAudioBytes": 4000000,
        "preferredClientSwitchBytes": 3500000
      },
      {
        "mimeType": "audio/ogg; codecs=opus",
        "maxAudioBytes": 4000000,
        "bitrateBitsPerSecond": 48000
      }
    ]
  }
}
```

服务端的 4.0 MB WAV 接受上限特意宽于新桌面端的 3.5 MB 切换阈值。这保留了现有的两分钟 WAV 客户端（约 3.84 MB），同时给新客户端在选择 Ogg 之前更多 multipart 与容器余量。

托管能力是一种协商协议，而非仅是展示元数据。只有当 24 小时内生成的鉴权服务端快照通告了能力版本 2 与兼容的 Ogg/Opus 策略时，才启用 600 秒云端推荐。如果能力缺失、早于 24 小时、来自版本 1 服务端、畸形，或窄于内置策略，桌面端取较低的安全结果。没有新鲜兼容能力时，云端保留历史的 30 秒回退；它绝不假设更旧的部署接受长上传。

一旦版本 2 桌面端发布，TalkMore 回滚策略即使全局标志停止通告扩展能力，也保留 Ogg 解析器与字节兼容的请求处理。能力撤回阻止刷新后的新长会话；它不是移除已发布或正在录音客户端所需解析器的许可。更新的鉴权响应可能出于传输安全缩短一个活跃的托管会话，即便普通的 provider/配置变更不会以其他方式修改进行中的截止时间。如果缩短后的截止时间已过，桌面端执行一次优雅停止，提交它能提交的最安全负载。

## 7. 问题 #83 录音启动架构

### 7.1 启动屏障

麦克风与 STT provider 并发启动：

```text
用户开始录音
  ├─ 在其平台音频线程上启动 CPAL 输入
  └─ 连接/准备 STT provider
          ↓
等待两者都报告就绪
          ↓
发布完全就绪的录音状态
```

音频就绪意味着输入流已构建且 `stream.play()` 成功。仅仅生成采集线程不算就绪。

现有的 `Preparing` 确认在热键转换后立即发射，因此 UI 在屏障挂起时绝不会显得无响应。麦克风在后端允许时即开始采集，即使 STT 连接仍待定。有界通道保留那些初始数据块，直到 provider 消费者就绪。最终的录音事件与定时器使用原始的音频就绪时间戳，因此已用时与 provider 限制都包含缓冲的启动音频。

### 7.2 缓冲与失败规则

- 通道容量由数据块时长派生，在默认 20 ms 块大小下代表 60 秒；
- 缓冲有界，以防止无响应的 provider 无限增长内存；
- 组合的启动屏障有 30 秒超时，之后两边取消并显示现有的可重试启动错误；
- 如果音频初始化失败，取消 provider 启动并返回现有的麦克风/设备错误路径；
- 如果 provider 初始化失败，停止采集、释放设备，并返回 provider 错误；
- 如果两者都失败，暴露一个确定性的主错误，并记录次要失败，不重复用户通知；
- 启动进行中取消与停止仍然有效；
- 不引入平台特定的固定 sleep。

CPAL 的 `stream.play()` 边界被 CoreAudio、WASAPI、ALSA、PipeWire 后端共享，但运行时行为仍必须在代表性设备上验证。

```json
  "generatedAt": "2026-07-22T10:00:00.000Z"
}
```

`revision` 序列化为十进制字符串，以避免 JavaScript 整数精度问题。在当前非原子发布中，状态查询返回兼容值 `"0"`，且不引用分阶段中的 `usage_revision` 列。真实的单调 revision 只在延后的原子配额切换时开始。

云端操作响应新增可选的 `usageSnapshot`。它们无需在每次请求重复所有权益字段。

### 8.2 快照排序（延后）

`quota` 表新增非空的 `usage_revision` bigint，默认为零。每次成功变更显示的配额计数或限制，都在同一事务中递增它。

客户端接受规则：

1. 拒绝 `userId` 与当前鉴权用户不匹配的快照。
2. 不管 revision，优先选择更新的 `periodStart` 而非较旧的周期。
3. 在同一周期内，只接受更大或相等的 revision。
4. 相等的 revision 可刷新元数据，但不能减少计数。
5. 登出或会话失效时清除当前用户关联。

这些规则防止较旧的网络响应覆盖较新的并发 STT/LLM 结果。

### 8.3 状态查询

鉴权后，`/api/subscription/status` 执行一次只读的业务数据查询，获取：

- 最新的相关订阅；
- 优先的激活许可，或在没有激活许可时的最新许可；
- 当前周期的配额行（如果存在）。

权益解析仍是返回行上的纯函数。缺失配额行表示为零用量，配合由权益派生的限制。GET 不得插入或更新配额。

当前查询必须只使用既有生产列，并返回 revision `"0"`；部署附加的原子计量迁移不是此状态优化的前置条件。

不要仅因 PostgreSQL 为七行表选择顺序扫描就强制加权益索引。在改变订阅/许可索引前，用真实数据检查组合的账户查询。为所需的每用户过期/reconciliation 路径添加 `(user_id, expires_at)` 操作索引，并在 staging 用 `EXPLAIN (ANALYZE, BUFFERS)` 校验该查询。

## 9. 桌面端 AccountSnapshotCoordinator

本节中持久的 Rust 协调器与原子响应契约一起延后。在当前发布中，现有的前端 auth store 持有状态数据，去重并发刷新，并在托管输出后刷新一次；9.2 节的活跃意图预热策略在 Rust 中独立实现，并在预热后丢弃其响应。

Rust 持有每个 Tauri 窗口共享的、设备级的 `AccountSnapshotCoordinator`。

职责：

- 为鉴权的 `userId` 加载最后一次成功的快照；
- 只持久化 plan/quota/capability 元数据，绝不持久化会话令牌、音频、转写或提示；
- 暴露本地的 `get_account_snapshot` 命令；
- 执行单一飞行去重的 `refresh_account_snapshot(reason)`；
- 跟踪当前进程成功的托管服务端/Neon 活动，而不把持久化的时间戳当作 Neon 仍然唤醒的证明；
- 应用 Rust 云端 provider 收到的更新的 `usageSnapshot` 值；
- 接受快照后发射一次 `account:snapshot-updated` 事件；
- 标记快照陈旧，而不清除其最后已知值；
- 登出或会话失效时清除账户级状态。

持久化快照必须以用户 id 为键。UI 只在 Better Auth 识别同一用户后才显示它。这避免在一个账户登录期间显示另一个账户的套餐。

### 9.1 刷新策略

在以下时机刷新：

- 会话身份已知后的应用启动；
- 成功的登录或深链令牌鉴权；
- 当当前行为已刷新访问权限时的密码/会话令牌轮换；
- 结账或许可激活返回；
- Account/Usage 页面进入；
- 显式的用户刷新；
- 主窗口获得焦点，仅当最后一次成功的服务端快照早于 30 分钟；
- 托管云端录音或 Ask 交互的开始，受下述活跃意图策略约束。

不在以下时机刷新：

- 固定定时器；
- 每次托盘显示；
- 每次 Ask 窗口显示；
- 胶囊显示/隐藏；
- 普通 BYOK 录音；
- 仅传输预热的 HEAD 请求。

所有触发器使用同一协调器，因此启动、焦点、账户页进入与深链不能产生重复的在途状态请求。

### 9.2 托管云端意图预热

移除五分钟轮询允许 Neon 挂起，这对计算节省是必要的，但可能在非活动后给第一次数据库支撑的请求增加几百毫秒。现有的启动 `HEAD /api/proxy/stt` 只预热 DNS/TLS/Vercel 路由；该路由不导出鉴权的 `HEAD` 处理器，且该请求不触及 Neon。它不是数据库预热机制。

协调器因此复用鉴权的只读账户快照查询作为活跃意图预热：

- 当已登录用户开始 TalkMore 云端录音时，如果当前进程中最近的 4 分钟内没有成功的鉴权状态或云端操作响应，则启动一次后台刷新；
- 绝不在打开麦克风、发布 `Preparing` 或接受音频前等待此次刷新；
- 使用正常的单一飞行路径，因此启动/会话刷新与录音意图不能重复同一请求；
- 如果返回更新的结果则更新本地快照，但不预留配额或创建配额行；
- 同一云端录音保持活跃时，在第 4 分钟与第 8 分钟重新评估；仅当最后一次成功的托管活动至少 4 分钟前才发出刷新；
- 录音停止、失败或切离托管云端时，立即取消未来的活跃录音预热；
- 当已登录用户打开托管 Ask 交互时，应用相同的单次 4 分钟新鲜度规则；不引入 Ask 窗口间隔；
- 绝不为 BYOK、本地 STT、直接 provider 上传、空闲胶囊、托盘可见性或未鉴权用户运行此策略。

至多一次 10 分钟云端录音会在开始附近、第 4 分钟、第 8 分钟产生状态预热，而当另一次真实云端操作已经触及 Neon 时，部分或全部被跳过。这些请求可归因于活跃使用；一个空闲的已登录桌面端仍不产生周期性的数据库流量。

预热失败在 Account/Usage 之外是静默的：保留缓存状态并继续录音。真实操作仍由服务端权威决定，并可能自行执行 Neon 唤醒。预热是重叠优化，绝非授权依赖。

### 9.3 启动与离线行为

- 本地应用数据与主外壳独立于 TalkMore 加载；
- 一旦知道用户身份，立即应用匹配的持久化账户快照；
- 服务端刷新在后台运行；
- 刷新失败保留快照与当前云端控制；
- 陈旧的展示不授权云端请求；服务端仍决定；
- 如果没有匹配的快照，Account/Home 依赖套餐的部分显示账户加载占位符，并抑制套餐特定的升级声明，直到服务端或现有鉴权数据确立套餐；
- 无论快照新鲜度如何，BYOK 功能保持可用。

### 9.4 窗口行为

- 主窗口持有阈值警告 toast；
- 胶囊与 Ask 通过它们现有的管线事件接收操作错误；
- 隐藏窗口可能错过或延迟 JavaScript 事件，而不影响正确性；
- 任何变为可见的窗口在渲染账户敏感 UI 前，通过本地命令读取当前 Rust 快照；
- Ask WebView 不再调用 `useAuthStore.initialize()`，因为它不持有账户展示或云端授权。

## 10. 云端配额服务

整节延后。它仍是未来切换所需的设，不得视为当前生产行为。

### 10.1 接口

遗留双表套餐与云端词套餐都使用同一个概念配额接口：

```ts
interface QuotaService {
  reserve(context: OperationContext, estimate: UsageEstimate): Promise<Reservation>
  settle(reservation: Reservation, actual: ActualUsage): Promise<UsageSnapshot>
  release(reservation: Reservation): Promise<UsageSnapshot | null>
}
```

实现在计数上可能不同，但共享：

- 服务端权益解析；
- 幂等的 operation/stage 键；
- 原子条件预留；
- 单调结算；
- 原子释放；
- 变更本身返回的快照；
- 稳定的错误信封。

### 10.2 原子性与幂等性

对托管云端词，`operationId` 与 `${operationId}:${stage}` 仍是幂等键。

未来的附加 schema 设计包含以下字段。在当前运行时 schema 与迁移日志中，它们被刻意缺席，直到隔离 PostgreSQL 阶段恢复：

- `quota.usage_revision bigint NOT NULL DEFAULT 0`；
- `cloud_usage_operation.quota_model text NOT NULL DEFAULT 'cloud_words'`；
- `cloud_usage_operation_stage.customer_meter text NOT NULL DEFAULT 'cloud_words'`，值为 `cloud_words`、`stt_seconds` 或 `llm_tokens`；
- `cloud_usage_operation_stage.reserved_customer_units integer NOT NULL DEFAULT 0`；
- `cloud_usage_operation_stage.settled_customer_units integer NOT NULL DEFAULT 0`；
- `cloud_usage_operation_stage.reservation_expires_at timestamp`；
- `cloud_usage_operation_stage.replay_count integer NOT NULL DEFAULT 0`。

现有的云端词 stage 从 `reserved_cloud_words` 与之前的已结算增量回填通用单元列，然后保留旧云端词列用于回滚兼容，直到更晚的清理发布。现有行以 revision/replay 计数零迁移；现有的已预留 stage 收到从其创建时间派生的过期时间。操作保留其现有的逻辑过期/保留角色。`(user_id, expires_at)` 操作索引与部分 stage 过期索引支持用户级附带式 reconciliation，而无全局扫描。

Reserve 必须原子地：

- 解析或校验当前权益；
- 在真实用量首次需要时创建当前周期配额行；
- 创建或找到操作与 stage；
- 拒绝过期或无效操作；
- 在不超限的条件下预留；
- 当计数变化时递增 revision；
- 返回当前快照。

Settle 必须原子地：

- 找到并锁定目标操作/stage；
- 为已结算的重试返回之前的结算；
- 只计算单调增量；
- 应用额外用量或退还超额预留；
- 更新内部 provider/计费计数；
- 标记 stage 已结算；
- 递增 revision；
- 返回当前快照。

Release 必须原子地：

- 对已结算或已释放的 stage 不做任何事；
- 恰好一次退还仍预留的量；
- 标记 stage 已释放；
- 当显示的用量变化时递增 revision；
- 在可用时返回当前快照。

目标是每次状态转换一次业务数据数据库往返。鉴权仍可由 Better Auth 或其现有的短生命会话缓存提供。正确性不得依赖缓存。

### 10.3 被放弃的操作

不要仅为用量操作添加周期性清理 cron。

每个预留的 stage 收到 15 分钟预留过期。父操作为幂等保留 24 小时，终态操作元数据保留 7 天，之后有界附带删除。

在一次真实配额变更开始时，在活跃事务内 reconciliation 该用户过期的预留 stage：

- 恰好一次退还仍预留的量；
- 标记它们已释放；
- 为完整的 24 小时重试窗口保留操作/stage 幂等数据；
- 只在有界附带维护中删除超过 7 天的终态操作。

状态转换是显式的：

- `reserved -> settled` 应用一次实际用量；
- `reserved -> released` 退还一次；
- 对同一终态重复 settle 或 release 返回其先前结果；
- 重试之前已释放的 HTTP 操作必须通过条件的 `released -> reserved` 转换与新配额检查，才能调用上游 provider；
- 在没有该重新预留的情况下结算已释放 stage，返回稳定 HTTP 409 `invalid_quota_transition`；
- 已结算 stage 在前 5 分钟内最多可授权两个同操作传输重放，匹配桌面端现有的三总尝试重试上限。这些重放不会对用户双重计费，仍受速率限制，并递增一个持久化的 replay 计数。进一步复用返回 HTTP 409 `operation_already_completed`。用户发起的重试创建新的操作 id。

如果用户永不返回，旧行不会唤醒计算。清理也可能在一次已活跃的运维维护操作中运行，但不通过新的常驻调度器。

## 11. 云端响应数据流

本节描述延后的操作快照契约。当前发布保留现有响应负载，并只在主输出送达后执行其非阻塞状态刷新。

### 11.1 非流式 STT 与 Ask

成功响应保持向后兼容：

```json
{
  "text": "transcription",
  "usageSnapshot": {
    "userId": "user-id",
    "periodStart": "2026-07-01T00:00:00.000Z",
    "revision": "43",
    "quotaModel": "cloud_words",
    "cloudWordsUsed": 1248,
    "cloudWordsLimit": 200000,
    "resetAt": "2026-08-01T00:00:00.000Z"
  }
}
```

Ask 使用 `answer` 而非 `text`。旧客户端忽略可选字段。

Rust 在确保主内容后解析快照。畸形的可选快照被记录并忽略；它不能把成功的转写或回答变成失败。

### 11.2 流式 LLM

TalkMore 代理必须不在结算元数据就绪前转发上游最终标记。

顺序：

1. 转发内容增量，不等待结算；
2. 拦截上游 `[DONE]` 标记；
3. 结算用量；
4. 发射内部 SSE 用量事件；
5. 发射最终 `[DONE]` 标记并关闭。

概念事件：

```text
event: opentypeless_usage
data: {"usageSnapshot":{...}}

data: [DONE]
```

现有的桌面端解析器忽略没有 OpenRouter `choices[].delta.content` 字段的 JSON 事件。新解析器识别 `opentypeless_usage`。内容流式与首 token 延迟不变，因为预留已在上游请求前发生，结算仍在流完成时。

如果客户端取消流，TalkMore 像今天一样结算部分用量。因为连接已断，无法投递用量事件；下一次成功操作或显式账户刷新纠正设备快照。

### 11.3 错误响应

稳定错误信封在服务器真相可用时，可能包含 `usageSnapshot`：

```json
{
  "code": "cloud_quota_exceeded",
  "error": "Cloud words used up. Please switch to BYOK mode or wait until reset.",
  "usageSnapshot": {
    "userId": "user-id",
    "periodStart": "2026-07-01T00:00:00.000Z",
    "revision": "44",
    "quotaModel": "cloud_words",
    "cloudWordsUsed": 200000,
    "cloudWordsLimit": 200000,
    "resetAt": "2026-08-01T00:00:00.000Z"
  }
}
```

桌面端在显示错误前应用快照。鉴权无效的响应仍通过当前类型化的失效路径清除云端身份。

## 12. 失败语义

状态刷新失败语义适用于当前发布。变更返回的快照与结算同步语义仅适用于延后的配额阶段。

### 12.1 状态刷新

- 超时、离线、429 或 5xx：保留当前快照，标记为陈旧，不在 Account/Usage 之外显示破坏性的全局错误；
- 带稳定失效会话代码的 401：清除云端身份与匹配的快照，然后显示现有的登录消息；
- 畸形的可选字段：使用兼容的遗留字段或最后有效值；
- 刷新绝不可仅仅因为新字段缺失而将配额字段重置为零。

### 12.2 预留与上游失败

- 预留失败发生在产生上游成本之前；
- 配额耗尽在观察到更新的权益或重置前不可重试；
- 瞬时的数据库或 provider 连接失败使用有界的重试与现有的用户可见重试行为；
- 上游失败幂等地释放预留 id；
- 释放失败被记录，并在下一次真实变更时 reconciliation。

### 12.3 内容存在后的结算失败

一旦上游 provider 成功产出用户内容，用户内容优先。

- 做总共三次幂等结算尝试，第二次与第三次之前分别延迟 100 ms 与 300 ms；
- 这些重试失败后，不丢弃转写、Ask 回答，或已流式的 LLM 文本；
- 返回/发射 `usageSyncPending: true`，不呈现虚假的新快照；
- 保留保守的预留作为服务端真相，直到后来的变更 reconciliation；
- 标记本地快照陈旧，但保留其显示值；
- 记录待结算与操作 id 的指标，不记录内容。

正常的成功仍像当前非流式路径一样等待结算。此回退仅针对晚期的设施失败。

### 12.4 购买与许可传播

结账与许可激活不使用普通的 30 分钟新鲜度规则。

返回时：

- 立即刷新；
- 如果预期的权益不可见，在立即尝试后 2、5、10 秒重试；
- 一旦预期的套餐/许可出现即停止；
- 在有界窗口后停止，并保留可见的手动刷新动作；
- 购买流程结束后不继续轮询。

这些罕见的、用户发起的请求是可接受的，因为它们保护高价值体验，且不创造连续的空闲计算。

## 13. 警告与展示规则

现有的配额与错误展示保持当前。依赖持久化或操作返回快照的规则与第 9–11 节一起延后。

- 使用一个共享 reducer 将状态与操作快照应用到前端 auth/account store；
- 保留遗留双表与云端词之间现有的配额模型区分；
- 只在从低于阈值跨越到达到/高于阈值时显示 90% 警告；
- 启动时加载持久化快照不重复警告；
- 只有主窗口持有主动的阈值 toast；
- 收到配额耗尽错误的管线仍显示其当前的简洁胶囊/Ask 错误；
- Account/Usage 在陈旧时可显示 `Last updated` 或 `Offline`，但普通的 Home 与录音界面保持整洁；
- 没有后台刷新在本地特性上显示阻塞式 spinner。

## 14. 成本与性能设计

### 14.1 预期请求减少

对于一个升级过的空闲桌面端：

- 之前：登录期间约每小时 12 次状态调用；
- 之后：零固定间隔调用；
- 典型一天：一次启动刷新加仅有意义焦点/账户/购买动作；
- 托管云端使用可能在用户意图处增加一次去重状态预热，且只对超过 4 分钟的录音在活跃使用边界处；
- 当前发布的托管操作只在输出送达后触发一次去重状态刷新；这替换了轮询，同时保持配额 UI 当前，而不增加停止到输出的延迟。

旧客户端继续其现有轮询行为。因此计算节省随桌面端版本采用率而增加。服务端不能在不带来陈旧授权数据或另一耐久缓存的情况下，安全抑制个性化的旧客户端状态响应。

### 14.2 延迟规则

- 主应用外壳就绪不等待状态端点；
- BYOK 录音开始不新增 TalkMore 请求；
- 托管云端录音开始于并行启动任何所需的 Neon 预热，且在音频采集前绝不等待它；
- 托管云端 WAV 部分最多 3.5 MB 的录音使用当前 WAV 上传；60 秒或更短的录音保留当前 60 秒超时，而更长的负载使用字节派生的超时；
- 只有更大的托管录音付出 Opus 容器收尾，且正常成功不得在用户停止后执行整段录音转码；
- 主路径不新增对象存储上传/下载跳转；
- 当前生产授权、预留、结算、释放顺序在本发布中保留；
- 云端 LLM 首 token 与 STT/Ask 最终输出延迟不被账户同步延迟；
- 一次用后状态刷新只在托管输出达到其正常的完成/空闲状态后开始，且非致命；
- 直接从原子变更返回快照仍属延后的配额阶段，并将最终移除那次用后读取；
- 状态业务数据在一次只读往返中获取；
- 当前生产变更/刷新实现保持不变；当原子阶段恢复时，它只能在真实 PostgreSQL 验证后移除该实现。

当前 16 kHz 单声道输入的预期托管上传大小：

| 时长 | WAV | 去除小容器开销前的 48 kbit/s Ogg/Opus | 选定的托管格式 |
|---:|---:|---:|---|
| 30 秒 | 0.96 MB | 0.18 MB | WAV |
| 60 秒 | 1.92 MB | 0.36 MB | WAV |
| 约 109 秒 | 3.50 MB | 0.66 MB | WAV 边界 |
| 10 分钟 | 19.20 MB | 3.60 MB | Ogg/Opus |

在受控的 2 Mbit/s 上行链路上，传输 3.6 MB 在协议开销之前约需 14.4 秒；19.2 MB 约需 76.8 秒，且也会被 Vercel 拒绝。因此压缩长路径减少了而非增加了主导的用户网络部分。Groq 文档将 WAV 记录为低延迟格式，这正是短录音不切换的原因。

意图预热刻意用少量真实使用查询换取延迟。[Neon 的 scale-to-zero 文档](https://neon.com/docs/introduction/scale-to-zero) 说明非活跃计算在 5 分钟后挂起，并在几百毫秒内重新激活。一次短云端录音通常在说话期间隐藏那次唤醒。一次 10 分钟录音可在开始附近、第 4 分钟、第 8 分钟发出预热，在停止时让数据库就绪；5 分钟活动后挂起尾部只接受真实云端使用，而非空闲应用存在。

不要记录令牌、音频、转写、问题、选中文本或提示。客户端版本、路由、计时、配额模型、稳定结果码，以及匿名操作结果已足够。

成功指标：

- 升级客户端没有五分钟节奏；
- 空闲升级客户端群体的状态请求减少超过 90%；
- 状态鉴权后一次业务查询；
- 现有生产配额状态转换内业务数据往返不增加；单往返变更目标属于延后的原子阶段；
- 在为期七天的版本匹配群体中，云端请求成功率下降不超过 0.5 个百分点；
- 对 60 秒或更短的托管录音，温暖与冷启动的 `record_stop_to_transcript_ms` p50 不劣化超过 50 ms 或 5% 中的较大者，p95 不劣化超过 150 ms 或 10% 中的较大者；
- 同期，云端 LLM 首 token p95 不劣化超过 100 ms 或 10% 中的较大者，相对于基线；
- 在受控的 10 Mbit/s 与 2 Mbit/s 链路上，一次 10 分钟编码上传分别在 p95 6 秒与 20 秒内完成客户端上传阶段；
- 一个配对的私有长格式语音语料显示，相对 WAV 的 WER/CER 总回归不超过 0.5 个百分点，且没有语言群体回归超过 1.0 个百分点；
- 一次 10 分钟云端录音有零采集丢弃块、每 20 ms 帧的编码器 p99 工作低于 5 ms，且在定义的低端设备集上平均进程 CPU 增加不超过 5 个百分点；
- 增量编码相对同时长的托管 WAV 基线，峰值常驻内存增加不超过 8 MiB，排除测试插桩；
- 本地外壳就绪与 BYOK 录音开始零新增网络依赖；
- Neon 活跃时间随升级客户端占比增加而下降。

基线必须从当前已发布桌面端对同一 TalkMore 部署与网络画像捕获。温暖与 scale-to-zero 冷启动分别报告；将二者平均是不可接受的。如果短录音、首 token、质量或采集门禁失败，即使功能测试通过，托管长格式能力仍保持禁用。

## 15. 推广与兼容

本文档是跨仓库契约，而非对一个大 PR 的要求。实现规划必须保留以下可独立测试与回滚的阶段。

因为契约横跨三个可独立评审的子系统，执行使用三个计划：问题 #83 启动就绪；TalkMore 账户/配额效率；以及 provider 感知的录制限制加托管音频传输。后两个计划的服务器端部分先于其桌面端消费者部署。

### 阶段 1：附加的 TalkMore 兼容性基础

- 新增嵌套账户/用量快照类型，同时保留所有现有响应字段；
- 新增版本 2 托管 STT 能力元数据，同时让缺失元数据对旧客户端安全；
- 将路由级文件/请求限制降低到部署的 Vercel 边界以下；
- 接受并校验现有 WAV 与新的 Ogg/Opus 格式，转发正确的媒体类型/文件名，并在配额工作前拒绝畸形或超时的音频；
- 为自适应客户端超时配置并校验 STT 函数时长；
- 添加不移除 WAV/Ogg 解析器兼容性的全局能力通告开关；
- 使状态只读并collapse其业务读取；
- 保留现有生产配额变更与响应行为；
- 让升级桌面端在托管输出送达后执行一次去重、非阻塞的状态刷新；
- 扩展服务端契约测试；
- 在改变桌面端轮询前部署并验证旧桌面端客户端。

本阶段内的部署顺序为：解析器/限制（能力通告关闭）、旧客户端验证、staging 格式/超时验证，然后才是版本 2 桌面端发布前的生产能力通告。

回滚：旧字段与路由行为仍可用；新字段可选且可忽略。

### 阶段 2：桌面端事件驱动账户同步

- 集中并去重刷新触发器；
- 移除隐藏 Ask 鉴权初始化；
- 移除五分钟间隔；
- 在云端录音/Ask 开始与活跃长录音边界处，新增去重、非阻塞的托管意图预热；
- 为启动、账户、待结账焦点、购买流程，以及托管输出后的一次用后刷新保留状态端点；
- 使并发刷新单一飞行，并确保用后刷新失败不能移除或延迟用户输出；
- 与原子配额响应契约一起延后 Rust 快照持久化、托管响应快照，以及跨窗口 revision 合并；
- 在开始配额重写前确认空闲升级客户端的请求减少。

回滚：桌面端回滚继续沿用未变更的遗留扁平状态字段。服务端兼容性基础对旧与新客户端仍安全。

### 延后阶段 3：原子配额切换

- 新增 `usage_revision`、stage 预留过期/replay 计数，以及操作 reconciliation 索引；
- 将遗留双表与云端词路径都移到统一配额接口之后；
- 实现原子 reserve、settle、release、replay，以及过期预留 reconciliation；
- 直接从变更结果返回快照，并移除阶段 1 临时最终读取；
- 移除矛盾的-in-memory 批处理/显式刷新行为；
- 在部署前运行真实 PostgreSQL 并发与幂等测试。

此阶段被所有者显式延后，因为项目当前不引入隔离的数据库测试环境。它并非其他阶段的发布门禁。在所需 PostgreSQL 测试能在生产外运行之前，不要实现服务切换、移除当前计费实现，或启用依赖分阶段 schema 的路由。

当前发布回滚：因为此阶段未发布，没有原子用量列可回滚。未来隔离数据库推广后，其迁移必须保持附加，以便路由处理可在不改变桌面端契约的情况下回到阶段 1 兼容实现。

### 阶段 4：Provider 感知的录制限制

- 新增 Rust 能力注册表与配置迁移；
- 新增仅托管的打包 Opus 编码器 worker 与基于字节的 WAV/Ogg 选择器；
- 向 Settings 与 Capsule 暴露解析出的能力；
- 将权威截止时间移到 Rust 并锚定到音频就绪；
- 新增优雅警告与自动停止原因；
- 将同一解析器应用于听写与 Ask；
- 协商能力版本 2，并针对较旧/畸形的服务端能力保留 30 秒云端回退；
- 端到端校验托管云端 10 分钟契约、自适应超时、负载限制、质量与短录音延迟。

回滚：provider 解析的 `max_recording_seconds` 镜像仍可读且对较旧版本安全。

### 阶段 5：问题 #83 集成与发布 QA

- 将现有的启动屏障实现与设计提交分开评审并提交；
- 运行单元、集成、构建、lint 与跨平台 CI；
- 在 Windows、macOS、Linux 上测试真实麦克风设备；
- 发布区分 provider 限制与旧全局 30 秒行为的发布说明；
- 在关闭问题 #81 与 #83 前监控。

各阶段可以是独立的提交、PR 与部署。服务端兼容性必须在消费快照的桌面端发布前落地。延后的原子配额阶段不得被打包进轮询移除与空闲计算改进中，也不得阻塞它们。

## 17. 验收标准

### 17.1 问题 #81 可在以下情况关闭

- Apple Speech 在 macOS 上保持一分钟上限；
- TalkMore 云端在桌面端与服务端都强制为 10 分钟；
- TalkMore 云端对短录音用 WAV，仅在托管路由字节预算要求时用 Ogg/Opus，并对不兼容服务端回退到 30 秒；

### 17.2 问题 #83 可在以下情况关闭

## 18. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 旧客户端继续唤醒 Neon | 优化服务端查询，按客户端版本测量，并让节省随升级采用率增长；不破坏兼容性。 |
| 移除空闲轮询暴露 Neon scale-to-zero 唤醒延迟 | 在真实云端意图处启动去重鉴权预热，与语音重叠，并仅在一次活跃长录音中续期。 |
| 缓存套餐在外部撤销后陈旧 | 服务端强制执行每次云端调用；配额/鉴权错误立即更新或失效客户端；焦点/账户刷新保留。 |
| 购买 webhook 延迟到达 | 使用有界的结账特定重试与手动刷新路径。 |
| 并发响应使显示配额回归 | 比较 `periodStart` 与原子 `usage_revision`。 |
| 隐藏 WebView 错过事件 | Rust 为共享状态；可见窗口通过本地命令读取。 |
| 晚期结算失败丢失用户内容 | 保留内容，标记用量待定，保留保守预留，并在后来变更时 reconciliation。 |
| Provider 变更已发布限制 | 保留带版本的 Rust 注册表，并在变更时重新校验文档。 |
| 自定义端点有未知限制 | 使用保守的两分钟 Auto 值与带显式警告的客户端绑定自定义上限。 |
| Vercel 在路由代码前拒绝 10 分钟托管 WAV | 保留短 WAV，为长托管录音协商版本 2 Ogg/Opus，并保持完整 multipart 体低于 4.2 MB。 |
| Opus 增加 CPU 负载或改变识别质量 | 在采集回调外用一个打包编解码器编码，为短音频保留 WAV，并在丢弃块、CPU、WER、CER 门禁上阻塞推广。 |
| 编解码器打包跨操作系统不同 | 固定并打包一个实现，避免系统编解码器，构建所有受支持架构，并运行真实设备打包/运行时测试。 |
| 更大的上传超过桌面端当前 60 秒超时 | 在 60 秒音频内保持 60 秒，并对更长的托管上传使用上限 180 秒的字节派生超时。 |
| 服务端/客户端格式推广顺序错乱 | 先部署解析器与能力版本 2；新桌面端在兼容元数据鉴权前保留 30 秒托管回退。 |
| 原子 SQL 重写改变计费行为 | 不在当前发布切换；保留现有计费公式与操作 id，然后在工作恢复时要求真实 PostgreSQL 并发测试与服务端优先推广。 |

## 19. 完成定义

当前问题 #81/#83 与计算效率发布仅在下述情况完成：

- 所有批准的产品限制与迁移规则已实施；
- TalkMore 云端 10 分钟音频在文档字节预算内穿越部署的 Vercel 路由，而短录音留在 WAV；
- #83 启动行为已实施并跨平台验证；
- TalkMore 向后兼容且服务端优先部署；
- 桌面端账户状态是事件驱动且本地有韧性；
- 现有生产配额行为保持兼容，且无路由意外依赖分阶段原子 schema；
- 升级桌面端中无固定的订阅轮询残留；
- 空闲计算节省不暴露云端停止到转写或首 token 延迟的发布门禁回归；
- 云端内容保持响应，且不被晚期用量同步失败丢弃；
- 无音频/转写内容被加入 Neon 或遥测；
- 自动化套件、生产构建、契约测试与三平台手动矩阵通过；
- 问题关闭仅在该行为存在于已发布发布后发生。

独立的原子配额里程碑仅当原子的、幂等的、返回快照的变更通过了指定的真实 PostgreSQL 并发与 replay 测试后才完成。该未来里程碑不属于当前发布的完成定义。
