# OpenTypeless 桌面端设置简化设计

日期：2026-07-12
状态：已批准实现
批准：用户审阅了运行中的 macOS 包，并于 2026-07-12 指示实现
范围：仅现有桌面设置与登录密码对话框

## 1. 目标

让现有的 P0/P1 桌面能力给人一种安静、明显、贴合当前 OpenTypeless UI 的 native 感。在保留所有已发布行为的同时，减少默认文案、重复的状态 UI、禁用控件以及面向重度用户的 관리 chrome。

## 2. 产品原则

- 默认屏幕解释“下一个决策”，而不是实现细节。
- 只有当用户确有需要管理的高级状态时，才出现高级控件。
- 一个系统条件对应一个主操作入口。
- 应用适配仍是一个克制的特性信号，而不是一个 app 陈列馆。
- 现有的路由、间距、排版、≤10px 圆角、本地 logo、紧凑对话框保持权威。
- 这个纯 UI 的规格不独立重定义密码、账户、云、配额、检测器、prompt、意图、词典、快捷键或备份契约。配套规格覆盖 prompt、权限与本地 provider 加固；云恢复行为记录在分支 handoff 与实现测试里，而非由本 UI 规格定义。

## 3. 通用设置

### 3.1 快捷键行

- 一个角色只有一个绑定时，只显示标签、快捷键录制器和添加动作。
- 不要为单一绑定显示 `Primary`、移动箭头或禁用的删除动作。
- 多个绑定时，只给第一个绑定标注 `Primary`。
- 用每个可管理绑定上的一个 More 菜单，替换原本一直可见的三个移动/删除控件。
- 次要绑定菜单在适用时提供 `Make primary`，在允许时提供 `Remove`。
- 添加快捷键立即开始捕获。绝不插入一个需要二次点击的被动 `—` 行。
- 添加行有可见的 Cancel 图标/按钮。Escape 仍是一个有效的独立快捷键，录制期间不被当作取消。
- 全局冲突与注册行为保持不变。

### 3.2 辅助功能权限

- 现有的顶部应用权限横幅仍是唯一的主“授予权限”入口。
- 从 General 中移除重复的 macOS 辅助功能区块和第二个“授予权限”按钮。
- 只有当平台/注册错误能提供顶部权限横幅之外的信息时，才保留它们。

## 4. AI 润色

- 从主设置流程中移除一直可见的 `Context and thought-aware support is best effort` / 认证状态行。
- 不要仅为这个被移除的展示去请求模型能力状态。
- 移除 `AI cleanup for dictation` 与 `Always translate output` 的辅助段落。
- 保留一段简洁的上下文适配说明，因为该行为并不直观。
- 保留选中文本说明，因为它传达了操作/token 范围。
- 代表应用 logo 行仅在 AI 润色与上下文适配都启用时激活。
- 禁用状态的 logo 仍可见但变暗；其无障碍标签说明适配已关闭。

## 5. 翻译

- 翻译仍是 AI 润色的一部分，因为它服务于 Always Translate、翻译快捷键与胶囊目标切换。
- 把可见概念从 `Target Language` 重命名为更短的本地化等价 `Translate to`。
- 把紧凑的目标控件直接放在 Always Translate 开关下方。
- 只有一个目标时，显示一个选择器和一个 Add 动作。不要显示单选、箭头、删除动作或独立的沉重区块。
- 多个目标时，显示当前目标选择器加一个 `Manage languages` 展开项。
- 只有展开管理状态时才显示逐目标选择器、排序与删除。
- 保留一对一到五的唯一目标契约，以及激活目标的兼容性镜像。

## 6. 场景与应用上下文

- 场景必须展示 AI 润色如何适配应用类型。顶部区块是 `App Writing Modes`，按语义应用族组织，而非 71 个 app 的陈列馆。
- 每个应用族行显示代表性的本地应用 logo、族标签、简短示例说明和紧凑的场景选择器。
- 选择器的默认选项是一个具体的默认模式名，如 `Email Format` 或 `Work Chat`，而不是 `Automatic`。
- 内置默认模式存在于应用族行中，不在下方作为独立的“内置场景库”重复。
- 内置默认模式也出现在 `My Scenes` 中，作为可编辑的默认场景，带 `Reset to default` 动作。
- 选择自定义场景时存储一个族分配，并替换该应用族的系统模式。
- 编辑默认场景只存储该场景的 prompt 覆盖，并立即改变其应用族的默认行为。
- 现有的 `family_scene_assignments` 是应用族场景选择的持久化存储与运行时输入。
- 精确的 app 覆盖仍是用户拥有的路径，用于特定的未知/自定义 app 或特定 app 的写作风格。
- 自定义场景仍是可复用预设，可分配给应用族。UI 不再暴露全局场景激活。
- 遗留的 `active_scene` 数据在运行时保持兼容，但新 UI 不应鼓励全局场景覆盖。
- 当存在安全的本地检测结果或既有用户映射时，AI 润色保留最近检测 app 的路径来创建精确 app 覆盖。
- 精确 app 覆盖 UI 不显示原始 bundle ID、URL、标题、匹配素材或 71 个 app 的陈列馆。

## 7. 词典

- 新增一个紧凑的分段控件用于 `Words` 与 `Corrections`。
- 只显示当前激活的编辑器与列表。
- 搜索、导入、导出、编辑、事务性导入与纠错行为保持共享不变。
- 切换分段不清除任何输入或数据。

## 8. 密码对话框

- 保留已批准的紧凑 380px 模态框与当前的校验/变更行为。
- 把向前与向后的键盘焦点困在对话框内。
- 焦点循环仍停在激活字段/动作内时，跳过禁用控件。
- Escape、背景关闭、忙状态防护、首字段聚焦与触发焦点恢复保持不变。

## 9. 无障碍与布局

- 不出现不可见的可得焦点的管理控件。
- 每个仅图标的动作都有无障碍名称与 tooltip。
- 菜单在 Escape 时关闭并把焦点恢复到触发者。
- 对话框保持在 720x480 最小视口内。
- 设置面板在 720x480 或 900x700 下不得出现横向溢出。
- 现有的 reduced-motion 与 token 行为保持不变。

## 10. 验证

- 新行为以测试优先方式开发，使用聚焦的 Vitest 套件。
- 现有 36 文件 / 320 测试的前端套件保持绿色。
- 现有 434 个 Rust 测试保持绿色。
- `npm run lint`、`npm run build` 与调试用 macOS app bundle 必须通过。
- 打包 app 的 QA 覆盖 General、AI 润色启用/禁用状态、带具体默认模式名的 App Writing Modes、精确 app 覆盖可达性、翻译单/多目标状态、词典分段、场景激活/清除，以及密码焦点循环。
- QA 期间不提交真实密码，也不改变 macOS 权限。

## 11. 完成定义

- General 在默认单绑定状态下不再显示重复的 Primary 标签或禁用的箭头/垃圾桶控件。
- 重复的 General 辅助功能 CTA 已移除。
- AI 润色默认文案显著缩短。
- 上下文 logo 准确反映上下文适配开关。
- 翻译在常见的单语言情况下是紧凑的。
- 场景展示应用族写作模式，带代表性应用 logo 与可编辑的场景选择。
- 当没有遗留 active Scene 或精确 app 覆盖时，族/默认场景 prompt 改变运行时场景选择。
- 当某个 app/默认/自定义场景 prompt 拥有输出形态时，跳过 Polish Style。
- 精确自定义 app 覆盖仍只能从安全的检测上下文或既有用户映射到达。
- 词典一次只显示一种维护模式。
- 密码焦点不能逃到模态框背后。
- 聚焦、完整前端、Rust、lint、build 与打包视觉门禁都通过。
