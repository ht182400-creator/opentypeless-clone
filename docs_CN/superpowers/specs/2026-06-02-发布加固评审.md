# 发布加固评审规格

日期：2026-06-02
目标发布版本：v0.1.31

## 范围

在 issue #46 之后评审当前发布候选版本，并在发布下一版之前加固其行为。

## 发现的问题

1. 录音取消后仍可能让过期的 STT 任务在之后完成。
   - 之前的 STT 完成通知在多个会话间共享。
   - 已取消的 STT 任务仍可能运行 provider 收尾逻辑，并在用户已经取消或已开始另一个会话之后追加文本。

2. 自定义 Whisper 复用了托管的 STT API Key。
   - 可选的本地/自定义 API Key 字段底层引用的是 `stt_api_key`。
   - 从托管 STT 切换到自定义 Whisper 时，可能把托管 provider 的 Key 发送到本地服务器。

3. 选中文本上下文需要更强的"不可信内容"措辞。
   - 选中文本是上下文，而非指令来源。
   - 提示词需要明确的指引，忽略 `<selected_text>` 内部的指令。

4. 选中文本捕获会拒绝与上次剪贴板文本相同的有效选择。
   - 之前的相等性检查是将复制的文本与剪贴板备份做比较。
   - 如果真实选择恰好等于上次的剪贴板文本，就会被丢弃。

5. 关于/发布版本显示过期。
   - `APP_VERSION` 被硬编码为 `v0.1.0`。
   - 发布工作流更新了包元数据，但没有注入前端版本。

## 期望行为

1. 取消录音会立即让当前活跃的 STT 会话失效，唤醒任意等待者，并阻止过期 STT 输出被发出或累积。
2. 自定义 Whisper 存储并发送 `stt_custom_api_key`；托管 STT provider 继续使用 `stt_api_key`。
3. 备份上传同时排除托管与自定义 STT API Key。
4. 选中文本捕获使用一个唯一的剪贴板哨兵值，从而忽略未变化的复制尝试，同时接受与旧剪贴板相同的有效文本。
5. 发布构建暴露 `VITE_APP_VERSION=v<release>`，使关于页显示真实的发布版本。
