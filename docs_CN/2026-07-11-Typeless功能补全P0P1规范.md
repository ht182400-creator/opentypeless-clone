## 1. 摘要

OpenTypeless 已具备一个强大跨平台语音写作产品的基础：全局听写、可选的 AI 润色、选中文本编辑、Ask Anything、翻译、本地历史、词典与纠错规则、可复用场景、BYOK provider、托管云端 provider，以及 macOS、Windows、Linux 上的桌面支持。

相较 Typeless 的剩余差距并非一组缺失的设置。核心差距在于：OpenTypeless 仍主要表现得像一个可配置的转写管线，而 Typeless 越来越像一个上下文感知的写作层——它理解用户正在哪里写作、期望得到什么结果、哪些语音片段是指令或纠错，以及结果应该出现在哪里。

本倡议的首要产品承诺是：

> 同一段口语化的想法，应在 Gmail、Slack、Docs、GitHub、代码编辑器或某个未知应用中成为不同但可直接使用的文字，同时保留相同的底层事实与明确的用户意图。

因此应用识别不是一个 logo 特性。logo 只是可选的反馈。产品价值来自自动将安全的写作策略绑定到检测到的上下文，使用户无需在每个应用里都手动切换场景或清洗同一份转写稿。

覆盖规模必须通过数据扩展，而不是靠一次性的管线分支。新增一个应用意味着向一个本地注册表添加一条确定的匹配器、语义族映射、可选的小型结构化覆盖、图标键与夹具。它不应要求新的 LLM 调用、独立的提示词，或新的 UI 界面。

本倡议使 OpenTypeless 默认具备上下文感知能力，同时保留其差异化优势：

- 本地优先的历史与设置
- BYOK 与自托管
- 明确的 provider 选择
- 克制的桌面 UI
- 无静默网页浏览
- 无基于内容的遥测
- 用户对场景与个人化的控制

本倡议同时弥补 `talkmore` 与桌面客户端之间的账户恢复与密码管理缺口。账户完整性是一条独立的 P0 发布轨道，不得与上下文智能的推广耦合。

### 1.1 版本 2.0 实现结果

本规范中完整的 P0 与 P1 功能范围已在隔离的 OpenTypeless 与 TalkMore 工作树中实现。最终实现包含：

- 33 个发布阻塞级参考应用画像，以及跨越全部十个语义族的 38 个扩展画像
- 一个后台检测器与 O(1) 的录音开始快照读取
- 确定的英语、简体中文、繁体中文语音意图路由

- 事务化的词典导入/导出与显式纠错创建
- 显式的设备本地「应用→语义族/场景」映射

第 23 节所记录的提交点，所有仓库级自动化测试、lint 门禁与生产构建均通过。跨平台真实物理应用识别、原生快捷键行为、实时事务化邮件投递，以及托管模型的语义评估仍属于部署验证，而非未实现的产品行为。

## 3. 问题陈述

### 3.1 主要问题

用户可以配置 OpenTypeless 产出良好的文本，但产品常常需要手动设置才能在当前任务中行为得当。浏览器中的 Gmail 可能被归类为通用浏览器。Slack、Google Docs、Notion、GitHub、支持工具、社交撰写器可能收到同样的通用润色行为。用户必须用人工场景选择或自定义提示词来弥补。

### 3.2 次要问题

- 语音纠错与旁注可能残留在最终文本中。
- 语音命令分裂在普通听写、选中文本关键词路由与 Ask Anything 之间，而非共享同一个意图模型。
- 翻译一次只支持一个配置目标。
- 词典管理缺少搜索、编辑、导入、导出，以及安全的纠错学习工作流。
- 个人风格以人工场景存在，但没有自然地关联到上下文。
- 账户用户可以注册与订阅，却无法恢复或更改密码。
- 云端会话可能在桌面端仍显示已登录时过期或被吊销。

### 3.3 为何重要

产品的承诺是：文本在用户已经工作的应用中可直接使用。一份技术上准确、但语气错误、保留了被丢弃的想法、路由到错误输出界面，或忘记密码后无法恢复的转写稿，都打破了这一承诺。

## 4. 目标用户与工作

### 4.1 主要用户

在多个桌面应用间反复听写的知识工作者：

- 在 Gmail、Slack、Docs、Notion、Linear 与浏览器之间切换的创始人或产品经理
- 听写提示词、缺陷、评审与技术笔记的开发者
- 在工作聊天与邮件语言之间切换的多语言专业人士
- 选择 BYOK 或本地模型的隐私敏感用户

### 4.2 次要用户

- 撰写重复工单回复的客户支持人员
- 使用选中文本解释与摘要的写作者与学生
- 需要完整账户生命周期的托管云端订阅者

### 4.3 待完成工作

- 当我自然说话时，把最终想法变成无需清洗就能发送的文本。
- 在应用间移动时，无需每次都让我切换模式即可适配写作。
- 当我选中文本并说话时，推断我是想编辑它还是理解它。
- 当我翻译时，让我在我使用的语言之间切换，而不必回到设置。
- 当 OpenTypeless 反复漏掉一个词时，让纠错变得容易，且不静默学习私人内容。
- 当我忘记密码时，让我安全地恢复付费账户。

## 5. 产品原则

1. 上下文应当自动，但用户意图必须胜出。
2. 用户主动选择的场景覆盖自动风格适配。
3. 安全与语义保真优先于风格、场景与个人化。
4. 低置信度的命令检测回退到普通听写。
5. 没有任何 P0 特性会给每次听写增加额外的 LLM 请求。
6. 浏览器 URL 路径、查询字符串与选中文本不存入历史。
7. 搜索只打开显式、允许列表内的目的地。
8. 桌面 UI 保持紧凑且以工作为导向。
9. `talkmore` 是账户与托管云端的唯一真相来源。
10. BYOK 与仅本地路径仍是一等公民。
11. 原始进程名、窗口标题与浏览器主机都是不可信的分类器输入，绝不作为提示指令。
12. 发布质量的语义保证仅适用于托管的参考模型与显式的认证模型矩阵；任意 BYOK 与本地模型仍属尽力而为。

已存在：

- 全局听写与 Ask 快捷键
- 按住与切换录音模式
- 流式/增量转写显示
- 选中文本捕获与关键词路由

- 每个角色仅存储一个快捷键绑定。

- Better Auth 邮箱/密码登录

- Google 与 GitHub OAuth
- 面向桌面端的 bearer 会话
- 账户关联
- 订阅、许可、云端配额、备份与代理 API
- 显式的桌面 CORS/可信源

已确认的缺口：

- `emailAndPassword.sendResetPassword` 未配置。
- 不存在重置密码网页。

## 7. 优先级与发布切片

P0 拆分为可独立交付的轨道。每个轨道有自己的发布门禁，可在不等待另外两个轨道的情况下进入生产。合并的 P0 里程碑是一个路线图标签，而非要求所有轨道一起部署。

### P0-A：上下文感知写作

1. Context Detector V2。
2. 语义上下文画像与小型应用特定覆盖。
3. 自动上下文提示绑定。
4. 思想感知听写与自我纠错夹具。
5. History 与 AI Polish 设置中的克制上下文反馈。

### P0-B：语音意图与输出放置

1. 共享意图模型。
2. 草稿插入。
3. 选中文本改写与回答路由。
4. 显式搜索路由与误报防护。

### P0-C：账户完整性

1. 忘记密码请求与邮件。
2. Web 重置密码完成。
3. Web 与桌面密码更改。
4. 会话吊销与桌面 bearer 令牌轮换。
5. 云端会话失效后的自动桌面登出。

推荐发布顺序：

1. P0-C 账户完整性，因为它关闭的是一个已有的账户安全缺口，且独立于听写行为。
2. P0-A 上下文感知写作，置于 `context_adaptation_enabled` 之后，带有即时本地开关。
3. P0-B 语音意图与输出放置，在保守的误报夹具对每个启用的语言都通过之后。

P1：

1. 多翻译目标与流程内切换。
2. 词典搜索、编辑、导入、导出与纠错建议。
3. 显式的本地风格画像、上下文到场景的分配，以及自定义应用映射。
4. 每个动作多个快捷键绑定。

P2 或更晚：

1. 自动观察插入后的编辑。
2. 从历史的静默个人风格学习。
3. 移动键盘。
4. 通过扩展实现的字段级浏览器理解。
5. 企业管理。

## 8. 跨仓库架构

### 8.1 职责归属

`opentypeless` 负责：

- 前台上下文采集
- 本地上下文分类回退
- 语音模式与意图路由
- 面向 BYOK/本地 provider 的提示组合
- 桌面 UI 与本地历史
- 桌面 bearer 令牌存储与 Rust 令牌同步

`talkmore` 负责：

- Better Auth 配置与账户数据
- 重置令牌与密码写入
- 验证、重置与安全邮件投递
- Web 重置与账户页面
- 托管云端提示执行
- 云端配额元数据与服务端安全控制

共享契约：

- 桌面与云端提示路径必须收到相同的归一化上下文与意图元数据
- 提示路径只能收到内部上下文画像标识、语义族与允许列表内的应用覆盖标识；它们绝不应收到原始进程名、窗口标题或浏览器主机作为指令
- 账户/会话 API 必须返回足够信息供桌面轮换令牌
- 任何仓库都不得在生产诊断中记录音频、转写稿、选中文本或完整提示内容
- TalkMore 服务端端点形态具有权威性；两个 lockfile 必须被钉版本，且发布前其兼容性须由契约测试覆盖

### 8.2 运行时流程

```text
OS 焦点/浏览器信号
  -> 异步 Context Detector V2
  -> ContextSnapshot 缓存

录音快捷键
  -> 读取缓存的 ContextProfile，不阻塞麦克风激活

音频
  -> STT
  -> 转写稿
  -> VoiceIntent 路由器
  -> 提示组合器
       安全 + 操作 + 思想规则 + 上下文 + 用户场景 + 词典
  -> BYOK/本地 LLM 或 TalkMore 云端 LLM
  -> 输出放置
       插入 | 替换选中 | 弹窗 | 打开允许列表 URL
  -> 本地历史诊断
```

## 9. P0-A 需求：上下文感知写作

### 9.1 Context Detector V2

#### 所需模型

```rust
pub enum ContextFamily {
    Email,
    WorkChat,
    PersonalChat,
    Document,
    ProjectManagement,
    DeveloperCollaboration,
    PromptOrCode,
    Support,
    Social,
    General,
}

pub enum ContextSource {
    NativeProcess,
    BrowserDomain,
    WindowTitle,
    Fallback,
}

pub struct ContextProfile {
    pub id: String,
    pub family: ContextFamily,
    pub app_label: String,
    pub source: ContextSource,
    pub confidence: f32,
}

pub enum AppReleaseTier {
    Reference,
    Extended,
}

pub enum NativeMatcher {
    BundleId(&'static str),
    Executable(&'static str),
    ProcessAlias(&'static str),
}

pub enum WebMatcher {
    ExactHost(&'static str),
    HostSuffix(&'static str),
}

pub struct TitleMatcher {
    pub anchored_marker: &'static str,
    pub required_browser_or_process: &'static str,
}

pub struct AppProfileDefinition {
    pub id: &'static str,
    pub label: &'static str,
    pub family: ContextFamily,
    pub override_id: Option<&'static str>,
    pub native_matchers: &'static [NativeMatcher],
    pub web_matchers: &'static [WebMatcher],
    pub title_matchers: &'static [TitleMatcher],
    pub icon_key: &'static str,
    pub release_tier: AppReleaseTier,
}

pub struct AppStyleOverride {
    pub artifact_kind: ArtifactKind,
    pub formality: Formality,
    pub density: Density,
    pub markup: MarkupPolicy,
    pub list_behavior: ListBehavior,
}
```

原始检测信号使用一个独立的仅供内部使用的 `ContextSignals` 值，包含归一化的进程身份、窗口标题与可选的浏览器主机。浏览器值只能包含归一化主机，绝不能包含路径、查询、片段、用户信息或完整 URL。

`ContextSignals` 是不可信输入。窗口标题与浏览器主机在确定性分类后即丢弃。一个独立的临时 `TargetAppGuard` 只能保留在插入前验证焦点所需的归一化可执行文件/bundle 身份与进程 ID；操作完成时即销毁。任一结构都不得发送给 LLM、TalkMore、历史、分析或普通生产日志。`app_label` 必须来自内部画像映射，而非原始标题或进程字符串。

应用注册表是位于 `app_detector/profiles.rs` 下的编译期本地数据源。它不在运行时下载。内置覆盖是结构化的策略增量，而非独立的自由形式提示。新增应用不能引入超出共享、已评审策略组合器的任意提示文本。

#### P0 参考覆盖

#### 注册表匹配规则

分类优先级：

1. 显式的本地用户映射
2. 当前台进程是受支持浏览器时的精确浏览器主机或经过评审的点边界主机后缀
3. 精确的 Native bundle 标识或可执行文件身份
4. 经过评审的原生进程别名
5. 允许列表内的、锚定的标题回退（较低置信度）
6. 安全的语义族回退
7. `general.browser` 或 `general.native`

要求：

- 画像 ID 使用稳定的 `{family}.{slug}` 标识，如 `email.gmail`、`chat.slack`、`message.wechat`、`doc.wps`、`project.linear`、`dev.github`、`code.cursor`、`prompt.claude`、`support.zendesk`
- 精确主机匹配优先于后缀匹配；后缀规则只在点边界处匹配
- 路径、查询字符串、任意页面文本与未评审的正则表达式都不是匹配器输入
- 重复的画像 ID、冲突的精确匹配器、不可达的匹配器，以及缺失标签/图标的条目会无法通过注册表校验测试
- 在启动时一次性构建精确主机、后缀、bundle ID、可执行文件与别名的查找索引；不要在每次录音时线性组合或扫描提示片段
- 标题匹配器不能基于弱子串将一个未知浏览器归类为 Email、WorkChat、PersonalChat、Support、Social 或 ProjectManagement
- 注册表大小不改变 LLM 请求数量或提示层数量
- 提示只收到族策略加上选定的结构化 `override_id`

#### 混合分类规则

检测可能识别出一个精确应用或站点，但提示由稳定的语义族加小型应用覆盖构建。不要为每个品牌维护一套完整的独立提示。

示例：

- Slack 使用 `WorkChat` 规则加小型 `slack` 覆盖。
- Gmail 使用 `Email` 规则加小型 `gmail` 覆盖。
- 未知的邮件客户端可使用 `Email` 而无应用覆盖。
- 飞书/Lark 原生默认 `WorkChat`；允许列表内的高置信度文档标题可能选中 `Document`，但 OpenTypeless 不检查私有文档 URL 路径来强制区分。
- WPS Office 在其所有写作界面使用 `Document` 行为，而非假装知道活跃字段或文件类型。
- Figma 使用 `ProjectManagement` 协作行为；在没有字段级 DOM 访问时，OpenTypeless 不声称能区分画布标签与评论字段。

#### 平台策略

录音开始架构：

- 维护一个后台 `ContextSnapshot` 缓存，而非在快捷键关键路径上派生检测工作
- 在前台应用变化时，以及受支持浏览器保持前台时更新缓存
- 在可用处使用 OS 原生焦点通知或钩子；权限安全的轮询可作为回退
- 除非 OS 焦点事件使快照失效，否则对受支持浏览器适配器的轮询每秒不超过一次
- 录音开始只执行 O(1) 的缓存读取
- 如果不存在快照，或最新快照早于两秒，对该次录音使用 `General` 并安排一次非阻塞刷新
- 浏览器适配器失败、缺少权限、检测器启动或缓存陈旧都绝不延迟麦克风激活
- 存储为该次录音捕获的快照，使 History 与 Settings 能展示用于该输出的上下文，而非当前显示 Settings 的应用

macOS：

- 用后台原生检测器或缓存适配器替换录音开始的 `osascript` 子进程
- 对 Safari、Chrome、Edge、Brave、Arc，在录音开始关键路径之外尝试通过已知浏览器适配器获取活跃标签页主机
- 在不弹窗的前提下检查浏览器自动化授权；绝不在应用启动或录音开始时触发新的浏览器控制权限对话框
- 当授权不可用时，使用进程/标题分类，直到未来的显式权限操作被加入既有权限 UI
- 自动化权限不可用时，安全回退到标题/进程启发式

Windows：

- 优先使用前台可执行文件与窗口标题
- 只在可靠处使用受支持浏览器的标题/域适配器
- 不要将 UI Automation 作为首个 P0 切片的发布阻塞项

Linux：

- 使用进程与标题启发式
- 不在 Wayland 下声称可靠的浏览器域检测
- 保留当前的能力告警与回退行为

#### 验收标准

- 在 Chrome 或 Safari 中的 Gmail，在主机或高置信度标题可用时不归类为 General。
- Slack 原生与 Slack Web 映射到同一语义族。
- GitHub 与代码编辑器使用不同的画像 ID，但兼容的技术保留规则。
- 每个参考级画像至少通过一条精确正向匹配器，以及它声明的每一类匹配器的三个禁止近似匹配夹具。
- 每个已发布的扩展级条目通过注册表校验与正向/负向匹配器夹具，即便它没有应用特定覆盖。
- 代表性的 Email、WorkChat、PersonalChat、Document、ProjectManagement、DeveloperCollaboration、PromptOrCode、Support、Social 画像在每个存在受支持界面的平台上手动核验。
- 未知网站不会基于弱子串变成 Email、WorkChat、PersonalChat、ProjectManagement、Support 或 Social。
- 上下文采集失败绝不阻塞听写。
- 发布性能测试中，录音开始的缓存读取 p95 低于 5ms。
- 原始标题、进程字符串、浏览器主机、完整 URL 与选中文本不会被发送到提示或默认存储；唯一的持久化例外是第 12.3 与 14.1 节定义的显式设备本地 P1 匹配器。

### 9.2 自动上下文提示绑定

新增 `context_adaptation_enabled: bool`，对新老用户默认 `true`。

优先级：

1. 安全与语义保真不变量
2. 操作与输出放置契约
3. 翻译/语言契约
4. 思想感知听写规则
5. 语义上下文族
6. 应用特定覆盖
7. 内置润色风格
8. 显式的个人风格画像（若启用）
9. 通过显式自定义应用映射分配的场景（若存在）
10. 主动手动选择的场景
11. 显式的自定义润色提示

后续层可细化风格，但不得覆盖安全、所请求的操作、语言或事实保真。

主动手动选择的场景在与自定义映射场景、自动上下文风格冲突时胜出。自定义映射场景仅在没有手动场景激活时适用。上下文仍提供技术保留与输出格式安全，但不得改写用户选择的语气。

内置应用覆盖只能调整制品类型、正式度、密度、标记与列表行为。它们不得引入用户未提供的收件人、问候语、落款、截止时间、指派人、缺陷状态、策略、承诺、话题标签、表情符号或事实声明。

#### 上下文行为示例

邮件：

- 产出邮件正文而非主题行，除非用户明确要求主题
- 使用完整句子与自然段落分隔
- 不编造问候语、收件人姓名、落款、截止时间或承诺

工作聊天：

- 优先使用一到三段短段落
- 除非说出，否则避免问候语与签名
- 仅当内容天然是列表时才用项目符号

个人聊天：

- 优先使用一到两条紧凑的自然消息
- 除非说出，否则避免职场状态语言、标题、问候语与签名
- 不添加用户未表达的表情符号、俚语或亲密感

开发者协作：

- 保留标识符、文件名、命令、代码片段、缺陷号与 Markdown
- 当语音支持时，优先使用问题、证据、下一步的结构
- 除非用户要求代码，否则不把听写变成代码

项目管理：

- 仅当语音提供时才显式写出状态、决策、障碍、责任人与下一步
- 精确保留缺陷 ID、日期、责任人与状态名
- 不编造工单标题、责任人、优先级、截止日、估算或状态转换

支持：

- 确认用户问题，但不编造策略或解决方案
- 保留具体步骤与责任归属

社交：

- 尊重说出的声明与语气
- 除非要求，否则不添加话题标签、表情符号、引流话术或未经支持的声明

### 9.3 思想感知听写

P0 必须覆盖不同的语义行为，而非把全部当成通用润色。

#### 所需行为

填充词去除：

- 去除犹豫音与空洞话语填充词
- 保留有意义的语篇标记，如 `however`、`actually`、`for example`

重复去除：

- 去除意外的重复词与重启动片段
- 保留有意的修辞性重复

即时自我纠错：

- `meet at seven, actually three` -> `Meet at three.`
- `send it to Sarah, no, Sam` -> `Send it to Sam.`

延迟自我纠错：

- 稍后的显式纠错可在中间插入语音之后仍替换更早的事实
- 保留所有无关内容

旁注处理：

- 显式的元短语，如 `for context, do not include this`，可引导输出而不出现在其中
- 普通的括号信息不得仅因听起来次要就被丢弃

乱序组织：

- 当说话者显式指示顺序时，组织步骤、列表与优先级顺序
- 没有清晰证据不得重排叙事或论证

描述词解析：

- 仅从当前话语、选中上下文、个人词典、纠错规则或显式可信上下文来源解析一个描述的名称
- 绝不静默搜索
- 证据缺失时绝不编造精确名称
- 不确定时保留口语描述而非幻觉

#### 实现约束

P0 使用既有的润色请求。它不得给每次听写增加第二次 LLM 分类或推理请求。

如果 AI 润色被禁用，OpenTypeless 返回 STT 结果，且不声称进行了思想感知语义清理。

#### 模型能力契约

本节中的语义质量门禁适用于：

1. 发布所用的托管云端参考模型与钉版本提示版本
2. 显式列入认证模型夹具矩阵的 BYOK 或本地模型/版本对

任意自定义 Base URL、未列入的 BYOK 模型与本地模型仍受支持，但属尽力而为。它们不会仅因请求是 OpenAI 兼容的，就继承 100% 关键事实保留或完整思想感知清理的产品承诺。

桌面不得为此区别新增沉重的 UI。设置可在模型选择或连接测试后显示一条简洁的兼容性说明。不支持不等于被阻止：用户可继续，同时诊断信息标识所选 provider 与模型以便在不记录内容的前提下复现失败。

#### 验收标准

- 所有关键名称、日期、数字、否定、URL、标识符与承诺都被保留，除非被显式纠正
- 被丢弃的替代方案不出现在输出中
- 一个含混的 `actually` 短语被加上标点，而非总是当作删除
- 低置信度重排保留原顺序
- 夹具输出不含编造的事实

## 10. P0-B 需求：语音意图与输出放置

### 10.1 共享意图模型

创建一个被普通听写、选中文本听写、Translate 与 Ask 共用的路由器。

```rust
pub enum VoiceMode {
    Dictate,
    Ask,
    Translate,
}

pub enum VoiceIntentKind {
    DictateInsert,
    DraftInsert,
    RewriteSelection,
    TranslateInsert,
    TranslateSelection,
    AskSelection,
    OpenQuestion,
    Search,
}

pub enum VoiceOutputPlacement {
    InsertAtCursor,
    ReplaceSelection,
    PopupAnswer,
    OpenUrl,
}

pub struct VoiceIntent {
    pub kind: VoiceIntentKind,
    pub placement: VoiceOutputPlacement,
    pub confidence: f32,
    pub search_provider: Option<String>,
}
```

### 10.2 路由规则

无选中文本的普通听写：

- 默认 `DictateInsert`
- 仅当归一化话语以所检测语音语言允许的精确允许列表命令前缀开头、且后接非空草稿负载时，才路由到 `DraftInsert`
- 英语 P0 前缀包括 `draft`、`write`、`compose`、`reply with` 等形式；中文 P0 前缀包括 `写一封`、`起草`、`帮我写`、`回复说` 等显式祈使形式
- 出现在句子后面、引号内、否定之后，或作为讨论主语的命令词属于普通听写
- 低置信度回退到 `DictateInsert`

带选中文本的普通听写：

- 显式改写/语气/长度/格式命令 -> `RewriteSelection`
- 显式翻译 -> `TranslateSelection`
- 信息性问题 -> `AskSelection` 与弹窗
- 含混语音 -> 非破坏性弹窗或普通听写，绝不破坏性替换

无选中文本的 Ask：

- 直接问题 -> `OpenQuestion` 与弹窗
- 显式草稿命令 -> 此前活跃字段中的 `DraftInsert`
- 显式允许列表搜索 -> `Search`

带选中文本的 Ask：

- 摘要、解释、比较或事实问题 -> `AskSelection` 与弹窗
- P0 对含混改写命令保持 Ask 非破坏性
- 破坏性替换仍通过听写/编辑选中流程可用

Translate：

- 无选中文本的 Translate 模式 -> `TranslateInsert`
- 带选中文本的显式翻译命令 -> `TranslateSelection`

### 10.3 搜索安全

P0 允许列表：

- Google
- YouTube
- Amazon
- GitHub

要求：

- 命令必须显式命名搜索意图
- `I should search for this later` 这样的提及属于普通听写
- 查询进行 URL 编码
- 不得生成任意 URL 或 shell 命令
- OpenTypeless 在 P0 中不获取或摘要搜索结果

### 10.4 路由器实现

- P0 中为确定性路由
- 使用基于词元或边界感知的语言语法，而非无限制子串匹配
- 每个语法包含正向前缀、必需的负载规则、否定守卫、引用/间接引语守卫与近似误报夹具
- 首个 P0-B 发布启用英语、简体中文、繁体中文命令语法
- 其他语音语言在各自语法与发布夹具通过前，默认非破坏性的 `DictateInsert`、`OpenQuestion` 或显式 Translate 模式
- 语法选择使用配置的显式 STT 语言；在自动语言模式下，只有精确启用语言的命令前缀并以无歧义的文字/边界匹配才能激活命令路由
- 所有十个桌面 UI 语言仍需 UI 本地化；UI 语言覆盖不意味着同一口语语言启用了破坏性语音命令路由
- 不为路由单独发起额外 LLM 调用
- 路由器种类与置信度可作为诊断信息存储
- 选中文本与完整话语内容不作为路由器遥测存储
- `DraftInsert`、`RewriteSelection`、`TranslateSelection`、`Search` 各自以特性标志开关，以便一个不安全路由可在不禁用听写的情况下关闭

### 10.5 验收标准

- `draft a follow-up email about tomorrow's launch` 在 Gmail 中插入一封草稿。
- `I need to draft a follow-up email tomorrow` 仍为普通听写。
- `do not draft this yet` 与 `she said "draft a reply"` 仍为普通听写。
- `make this warmer` 在使用听写/编辑模式时替换选中的邮件文本。
- `what does this mean?` 带选中时打开紧凑回答。
- `search React tutorials on YouTube` 打开编码后的 YouTube 搜索。
- Ask 与听写共享相同的意图类型定义。
- 任何插入或替换前都测试焦点恢复。
- 每个启用的命令语言以零破坏性误报通过其正向、否定、引用、含混与代码/标识符阻断夹具。

## 11. P0-C 需求：账户完整性

### 11.1 真相来源

`talkmore` 拥有密码重置令牌、密码哈希、账户关联、会话与邮件投递。桌面不得实现并行的重置令牌系统。

### 11.2 忘记密码

入口：

- TalkMore Web 登录
- OpenTypeless 桌面账户登录视图

流程：

1. 用户输入邮箱。
2. Web 或桌面以 `{ email, locale }` 调用 TalkMore 拥有的包装端点；客户端不能提供 `redirectTo` 或其他回调 URL。
3. TalkMore 对照已部署语言列表校验语言，并构造规范的同源回调 `https://www.opentypeless.com/{locale}/reset-password`。
4. TalkMore 在服务端以该规范回调调用 Better Auth `requestPasswordReset`。
5. 无论账户是否存在，UI 始终显示相同的成功响应。
6. 当账户存在时，TalkMore 通过 Resend 发送 OpenTypeless 品牌的邮件。
7. 邮件链接经过 Better Auth 令牌校验。
8. 用户带着已校验的令牌进入本地化的 TalkMore 重置页面。
9. 用户输入并确认新密码。
10. TalkMore 调用 `resetPassword` 并吊销既有会话。
11. 成功将用户带回登录页。任何重置令牌都不传递给桌面应用。

安全要求：

- 令牌有效期：一小时
- 令牌一次性使用
- 对未知邮箱返回通用响应
- 保留并校验 Better Auth 限流
- 包装器使用至少与底层 Better Auth 路由同样严格的限流，基于客户端 IP 加单向归一化邮箱键；服务端到服务端的回环地址不得合并或绕过调用方限制
- 通过 `disabledPaths` 或等价的服务端守卫禁用公开的 Better Auth `/request-password-reset` 路径；TalkMore 包装器是唯一的公开重置请求入口
- 包装器可在内部调用服务端的 Better Auth API，但任何浏览器或桌面请求都不能绕过它并把 `redirectTo` 提交到默认端点
- 包装器忽略未知请求字段，绝不重定向到客户端提供的源
- 生产重置回调使用仅包含规范 OpenTypeless HTTPS 重置页的专用精确允许列表；宽泛的 Better Auth/CORS 可信源、Tauri 源与生产启用的 localhost 源绝不接受为重置回调
- localhost 重置回调只存在于开发专用配置中，且不能在生产构建中启用
- 配置 Better Auth `advanced.backgroundTasks.handler` 为部署平台的请求生命周期原语，使 `runInBackgroundOrAwait` 能在响应之后完成 Resend 投递而不被终止
- 邮件投递成功与失败由针对所配置后台任务处理器的集成测试覆盖
- `revokeSessionsOnPasswordReset: true`
- 重置令牌必然经过 Better Auth 邮件/回调 URL，但绝不写入应用日志、分析、本地存储、桌面历史或持久化页面状态
- Better Auth 日志输出被包裹或净化，使未知账户的重置尝试不记录所提交的邮箱地址或带令牌的 URL
- TalkMore 重置页将回调令牌读入内存，并立即用 `history.replaceState` 从可见地址移除
- 重置页为 `noindex` 并使用 no-referrer 策略

### 11.3 更改密码

凭证账户：

- 要求当前密码
- 要求新密码与确认
- 执行 Better Auth 最小与最大长度
- 默认 `revokeOtherSessions` 为 `true`

仅 OAuth 账户：

- 不显示必然会失败的当前密码表单
- 显示克制的 `Set password` 操作
- 要求已验证的 OAuth 邮箱已验证；若未验证，发送验证邮件并阻止创建密码
- 验证后，调用 TalkMore 拥有的 `/api/opentypeless/auth/set-password` 服务端端点
- 该端点要求已认证会话，校验 `emailVerified`，校验不存在凭证 provider，并在服务端调用 Better Auth `setPassword`
- 客户端绝不直连仅服务端可用的 Better Auth `setPassword` API，也绝不收到密码哈希

已关联 OAuth 加凭证账户：

- 显示 `Change password`
- 更改密码不会解除 Google 或 GitHub 关联

账户能力检测：

- Web 与桌面在认证后调用 Better Auth `listAccounts`
- 返回的 `credential` provider 映射为 `present`；客户端绝不请求或检查密码哈希
- 没有凭证账户的社交 provider 映射为 `none`
- 加载或端点失败映射为 `unknown` 并隐藏密码变更操作，而非猜测
- provider ID 可用于 UI 行为，但不写入听写历史

### 11.4 桌面令牌轮换

当桌面调用 `changePassword({ revokeOtherSessions: true })` 时，Better Auth 返回新的会话令牌。

桌面必须：

1. 替换 `localStorage.session_token`
2. 以新令牌调用既有的 Rust `set_session_token` 命令
3. 刷新会话与订阅状态
4. 保持当前桌面已登录
5. 在测试中拒绝旧令牌

### 11.5 无效会话处理

新增一条集中化的跨运行时桌面认证失效路径。

TalkMore 已认证的云端端点返回稳定的 JSON 错误信封：

```json
{
  "error": {
    "code": "AUTH_SESSION_INVALID",
    "message": "Session expired"
  }
}
```

所需的机器码：

- `AUTH_SESSION_INVALID`：所提供的 OpenTypeless bearer 会话已过期、被吊销或无效；HTTP `401`
- `AUTH_REQUIRED`：未提供 OpenTypeless bearer 会话；HTTP `401`
- `QUOTA_EXCEEDED`：账户有效，但托管云端配额阻止了请求；HTTP `403`

托管云端 STT、LLM、Ask、订阅、备份及其他已认证路由必须保留这些码。它们不得要求桌面从状态码或人类可读消息推断账户状态。

Rust 新增一个专有的 `CloudSessionInvalid` 错误，区别于 provider-key `Auth` 与配额错误。当托管云端响应包含 `AUTH_SESSION_INVALID` 时，Rust 发出一个 `auth:session-invalid` Tauri 事件。BYOK/本地的上游 `401` 绝不产生此错误或事件。

前端拥有一个幂等的 `invalidateCloudSession()` 动作，Tauri 事件与 TypeScript API 响应都使用它。并发失败合并为一次状态转换与一次通知。

在证明会话无效的已认证云端响应上：

- 移除本地令牌
- 清除 Rust 令牌
- 重置托管云端账户与配额状态
- 保留 BYOK 配置与本地历史
- 显示一条简洁的 `Session expired. Sign in again.` 通知
- 不为每个失败请求重复显示同一通知

BYOK 模式下的 provider-key `401` 不得让用户登出 OpenTypeless 账户。

`AUTH_REQUIRED` 可显示正常的登录要求，但不声称会话已被吊销。`QUOTA_EXCEEDED` 保留已登录状态并遵循既有配额 UI。

### 11.6 邮件与品牌一致性

- 重置、验证与密码已更改邮件使用 `OpenTypeless`
- 从事务性邮件 HTML 中移除残留的 `TalkMore` 标题
- 包含纯文本回退内容
- 包含令牌过期措辞
- 密码邮件中绝不包含订阅或配额细节
- 使用 Better Auth `onPasswordReset` 做重置后的安全通知
- 使用服务端 Better Auth after 钩子发送成功的 `/change-password` 通知；不要信任单独的客户端触发通知请求
- 通知投递失败不回滚成功的密码重置或更改

### 11.7 验收标准

- Web 与桌面可在不泄露邮箱是否存在的情况下请求重置
- 客户端提供的重置回调、生产 localhost 回调与非 HTTPS 回调在到达 Better Auth 之前被拒绝或忽略
- 直连公开的 Better Auth `/request-password-reset` 返回 `404` 或等价的非操作响应
- 过期或重用的令牌不能重置密码
- 密码重置吊销旧的浏览器与桌面会话
- 桌面更改密码轮换并持久化其令牌
- 仅 OAuth 用户只能通过已验证的已认证账户经 TalkMore 服务端包装器建立密码
- 被吊销的桌面会话在下次已认证云端请求时被清除
- 同时的 Rust 与 TypeScript 无效会话响应产生一次状态重置与一次通知
- 仅本地/BYOK 使用在云端登出后仍可用

- 用户分配覆盖内置上下文语气
- 语义族到场景的分配仅在用户显式在云端备份中包含设置时才能同步
- 自定义应用匹配器保持设备本地，永远排除在云端备份之外，因为 bundle ID、可执行文件身份与主机都是平台特定的上下文标识

- 一个动作的所有绑定共享该动作的既有按住/切换行为

- 账户输入有持久可见或视觉隐藏的标签，而非依赖占位符
- 账户输入使用正确的 `autocomplete` 值，包括 `name`、`email`、`current-password`、`new-password`
- 登录/注册切换暴露 tab 或等价的选中状态语义
- 通用的密码重置成功与失败状态使用适当的礼貌 `aria-live` 区域
- 菜单在 Escape 时关闭并恢复焦点
- 文字在最小支持桌面窗口尺寸下不溢出
- 发布前所有十个桌面语言文件中都存在所有新字符串
- 无字号随视口宽度缩放

## 14. 隐私与云端契约

### 14.1 本地数据

- 上下文画像与简短应用标签可在历史启用时随历史存储
- 原始进程名、原始窗口标题与浏览器主机只是分类器输入，默认不存储
- 唯一的持久化例外是显式的 P1 自定义映射，它只在本地存储用户批准的归一化 bundle ID、可执行文件身份或精确主机，加上确认的短标签；它绝不存储窗口/页面标题、路径、查询、文档名或页面文本
- 完整 URL、选中文本与重置令牌绝不存储
- 个人风格与词典建议在显式备份前保持本地
- 自定义应用映射永远排除在 TalkMore 备份之外；只有无匹配器的族到场景分配可通过既有的显式设置备份选项包含

历史存储迁移：

- 新增 `context_profile_id` 与 `context_label` 字段；新条目只写入映射值，如 `email.gmail` 与 `Gmail`
- 只将目标进程身份保留在用于焦点恢复的内存 `TargetAppGuard` 中；不将其复用作历史元数据
- 前端事件只暴露映射的上下文标签/画像；目标进程身份保留在 Rust 内
- 在一个事务中，将已知遗留 `app_name` 值映射到新字段，将未知非空值映射到 `general.native` / `General`，迁移成功后清除遗留原始值
- 旧数据库与导出仍可读，且迁移回滚保留先前表完好

### 14.2 TalkMore 数据

TalkMore 可存储：

- 用户、账户、会话、订阅、权益与配额记录
- 幂等配额记账所需的操作 ID 与数值用量元数据

TalkMore 不得持久化或记录：

- 上传的音频
- 原始转写稿
- 润色输出
- 选中文本
- Ask 问题或回答内容
- 完整 LLM 消息
- 密码值或重置令牌
- 原始进程名、窗口标题或浏览器主机
- 来自密码重置诊断日志的提交邮箱值或带令牌链接

上游 STT/LLM provider 处理须单独记录。除非所选 provider 与账户契约支持该声明，否则 OpenTypeless 不得声称端到端零保留。

### 14.3 诊断

允许的生产诊断：

- 阶段名
- 时长
- provider ID
- 响应状态
- 字符/词计数
- 上下文画像 ID
- 意图种类
- 截断布尔标志

禁止的生产诊断：

- 内容体
- 选中文本
- 浏览器路径或查询字符串
- 授权头
- 会话令牌
- 邮件重置链接

## 15. 成功指标与发布门禁

本产品是本地优先的，因此 P0 发布决策使用无内容的质量门禁，而非强制的用户内容分析。

### 15.1 主要质量门禁

- 所有语义输出门禁针对钉版本的托管参考模型与提示版本运行；认证的 BYOK/本地模型对在进入认证矩阵前运行同一套件
- 本地注册表以唯一 ID、无冲突精确匹配器、无可及条目与完整标签/图标校验
- P0 包含至少 30 个跨越 Email、WorkChat、PersonalChat、Document、ProjectManagement、DeveloperCollaboration、PromptOrCode、Support、Social 的参考应用界面
- 受支持上下文扩展语料准确率：至少 95%
- 未知站点误分类率：在至少含 100 例的未知上下文语料中至多 2%
- 每个上下文输出阻断项在保持共享事实集的同时满足其画像所需风格与禁止适配不变量
- 显式意图真正例率：在每个启用的命令语言中至少 95%，而非仅在聚合总数中
- 破坏性意图误报：在发布阻断集中为零
- 关键事实保留：阻断夹具中名称、数字、日期、否定、标识符与承诺 100%
- 普通 P0 听写无额外 LLM 请求
- 提示组合恰好包含一种语义族策略与至多一种结构化应用覆盖；新增注册表条目不增加无关应用的提示层

每个发布报告记录桌面提交、TalkMore 提交、操作系统、模型/provider 标识、提示版本、STT 夹具来源、温度、语料版本与通过/失败计数。没有语料大小与版本的百分比不是发布结果。

### 15.2 性能护栏

- 上下文检测不增加网络请求
- 读取缓存上下文快照在受支持原生路径上至多 5ms p95
- 上下文刷新工作绝不在录音开始关键路径上同步执行
- 索引注册表查找在合成的 500 条目注册表基准中低于 2ms p95
- 后台上下文监视在发布基线机器上、五分钟空闲/焦点切换夹具中平均低于 1% CPU
- 麦克风激活 p95 相较 Phase 0 平台基线退步不超过 20ms
- 提示组合保持本地，相对 provider 延迟为亚毫秒
- 对麦克风激活、取消或焦点恢复无回归
- 账户恢复不影响 BYOK 启动或听写

### 15.3 UI 护栏

- 空闲胶囊尺寸不变
- 活跃胶囊高度不变
- 在支持的最小窗口尺寸下，Settings、History、Ask 或 Account 无水平溢出
- 语言奇偶测试通过

### 15.4 账户门禁

- 重置请求、有效重置、过期令牌、重用令牌、凭证更改、仅 OAuth 设置密码、令牌轮换与会话失效都有自动化覆盖
- 通用忘记密码响应在 UI 契约层面对已存在与未知账户完全相同
- 重置与更改绝不记录凭证或令牌
- 生产重置请求不能重定向到 localhost、Tauri 源、任意可信源、HTTP 或不支持的语言路径
- 默认的公开 Better Auth 重置请求路由被禁用；只有规范的 TalkMore 包装器在工作
- 托管云端无效会话、缺失会话、配额与 BYOK provider 认证的失败可由机器契约区分

## 17. 依赖与风险

### 17.1 依赖

- 用于前台上下文的 OS/浏览器 API
- 既有的 Tauri 权限与平台能力报告
- Better Auth 密码与会话端点
- Resend 投递与 OpenTypeless 域名配置
- 在暴露桌面「忘记密码」前需先部署 TalkMore 重置页的 Web 部署
- 新账户状态的完整桌面与 TalkMore 语言键
- 钉版本、经契约测试的 Better Auth 客户端/服务端版本组合

### 17.2 风险与缓解

浏览器检测变得脆弱：

- 使用语义族与归一化主机规则
- 保留标题匹配作为较低置信度回退
- 未知上下文保持 General
- 在后台刷新检测并在录音开始读取缓存

应用注册表变成难以评审的品牌例外集合：

- 使用单一类型化注册表模式与共享语义族策略
- 每个应用至多一个小型结构化覆盖
- 在校验测试中拒绝任意内置提示字符串、重复匹配器与不可达条目
- 保持参考级与扩展级明确，使长尾新增不静默扩展 P0 发布范围

超级应用在一个进程或主机内暴露聊天、文档、任务与支持：

- 保守地分类应用级默认
- 只对子界面使用经过评审的高置信度标题标记
- 在 P0/P1 中绝不检查 URL 路径、页面文本或 DOM 内容
- 当应用级行为不是期望的族时，让用户创建显式本地映射

窗口标题或浏览器页面注入提示指令：

- 将每个原始信号视为不可信分类器输入
- 只向提示组合发送内部画像/族/覆盖标识
- 分类后丢弃原始信号，并将其排除在历史、TalkMore 与生产日志之外

上下文风格改变用户语意：

- 硬性语义保真提示层
- 关键事实夹具
- 用户场景覆盖
- 上下文适配开关

任意 BYOK/本地模型无法遵循语义保真规则：

- 将发布声明应用于钉版本的托管参考模型与认证模型矩阵
- 保持未列入模型作为尽力而为可用
- 在无内容诊断与夹具结果中报告 provider/模型标识

意图路由器执行了意外命令：

- 带显式前缀与负载要求的边界感知语言语法
- 否定、引用、讨论、代码与标识符守卫
- 低置信度回退
- 破坏性误报阻断测试
- 含混时 Ask 保持非破坏性

个人化带来隐私顾虑：

- P1 是显式且本地的
- 自定义应用映射只持久化用户批准的精确 bundle/可执行文件/主机，绝不为标题或 URL 路径
- 自定义应用匹配器绝不进入设置备份；无匹配器的族到场景分配保持可选
- 无静默历史训练
- P0/P1 中无插入后监视

密码重置泄露账户存在：

- 通用 UI 契约
- 对未知账户的 Better Auth 合成工作
- 非阻塞的无服务器安全邮件投递

密码重置将令牌重定向到广泛信任的桌面或 localhost 源：

- 不接受来自 Web 或桌面客户端的回调 URL
- 在 TalkMore 构造规范的同源 HTTPS 回调
- 维护一个独立于 CORS 与 Better Auth 可信源的专用重置回调允许列表
- 针对 localhost、Tauri、HTTP 与不支持路径测试生产配置

密码更改后桌面丢失当前会话：

- 在刷新账户数据前消费返回的替换令牌
- 集成测试 localStorage 与 Rust 令牌状态

Better Auth 客户端/服务端版本漂移：

- 将 TalkMore 的服务端契约视为权威
- 钉版本两个依赖解析用于发布

### 23.3 最终上下文契约

检测器在后台启动并写入不可变的 `ContextSnapshot` 缓存。录音开始读取缓存，绝不同步执行浏览器自动化或进程发现。缺失或陈旧快照返回 General 并安排刷新。

内置覆盖是数据驱动的：

- 33 个 `Reference` 画像，带打包的 14px 到 16px 本地 WebP 标记
- 38 个 `Extended` 画像，使用族字形，除非存在已评审资源
- 共 71 个内置画像
- 精确主机、点边界后缀、bundle ID、可执行文件、进程别名与锚定标题索引
- 针对重复 ID、冲突精确匹配器、畸形画像与匹配器可达性的注册表校验
- 每个已发布画像声明的匹配器的正向与禁止近似匹配测试
- 合成 500 画像索引查找基准，2ms p95 上限

分类优先级实现为：

1. 已启用的显式本地映射
2. 受支持浏览器的精确主机或评审过的主机后缀
3. 原生 bundle ID 或可执行文件
4. 评审过的进程别名
5. 绑定到已知进程/主机的锚定标题回退
6. 安全族回退
7. `general.browser` 或 `general.native`

只有以下归一化值能跨越从检测到提示组合或历史：

```text
profile_id, family, mapped label, mapped icon key, structured override_id
```

原始进程名、可执行文件路径、窗口标题、浏览器路径、查询、片段与页面内容被排除。被 `TargetAppGuard` 使用的精确进程/bundle 身份在 Rust 中保持临时，仅用于输出放置安全。

### 23.4 最终提示与意图契约

提示组合器应用一个共享的思想感知策略、恰好一种语义族策略，以及至多一种结构化应用覆盖。手动场景与显式自定义提示对语气仍具权威性，但不能覆盖操作、语言、安全或语义保真约束。没有任何上下文特性增加第二次模型请求。

确定性意图路由器被 Dictate、Ask、Translate 与选中文本流程共用。发布语法与夹具计数为：

| 口语语言 | 带版本案例 | 支持路由行为 |
| --- | ---: | --- |
| 英语 | 277 | 草稿、改写、翻译、问题、允许列表搜索 |
| 简体中文 | 262 | 草稿、改写、翻译、问题、允许列表搜索 |
| 繁体中文 | 262 | 草稿、改写、翻译、问题、允许列表搜索 |

每个语料包含正向命令，以及否定、引用、讨论、含混、类代码、标识符、空负载、错误模式与禁用标志案例。不支持的口语语言使用非破坏性回退行为。

输出放置是一个类型化执行器契约：

| 意图 | 放置 |
| --- | --- |
| `DictateInsert`、`DraftInsert`、`TranslateInsert` | `InsertAtCursor` |
| `RewriteSelection`、`TranslateSelection` | `ReplaceSelection` |
| `AskSelection`、`OpenQuestion` | `PopupAnswer` |
| `Search` | 经 provider 允许列表的 `OpenUrl` |

执行器在插入/替换前恢复并验证捕获的目标。目标不匹配时安全失败，而非写入新聚焦的应用。

### 23.5 最终账户与云端契约

TalkMore 是唯一的密码与托管会话权威。已实现的公开 OpenTypeless 账户端点为：

```text
POST /api/opentypeless/auth/request-password-reset
POST /api/opentypeless/auth/set-password
```

重置包装器只接受 `{ email, locale }`，归一化邮箱，忽略未知重定向字段，从 `BETTER_AUTH_URL` 构造回调，并对已接受的请求（无论账户是否存在）返回相同的 `202 {"ok":true}` 响应。它应用每 IP 与 SHA-256 归一化邮箱桶。公开的 Better Auth `/request-password-reset` 路径被禁用。

密码重置使用一小时令牌，吊销会话，从可见重置页 URL 剥离令牌，并发送 OpenTypeless 品牌的 HTML 与文本邮件。重置、验证与密码更改日志值经过令牌/URL/邮箱净化。Next.js `after()` 被配置为 Better Auth 后台任务生命周期钩子。

密码能力为 `present`、`none` 或 `unknown`，源自 Better Auth 账户 provider。能力为 unknown 时隐藏变更操作。已验证仅 OAuth 账户使用已认证的 TalkMore 包装器，它在调用服务端密码 API 前拒绝未验证用户与已有凭证 provider 的用户。

托管已认证 API 使用稳定信封：

```json
{
  "error": {
    "code": "AUTH_SESSION_INVALID | AUTH_REQUIRED | QUOTA_EXCEEDED",
    "message": "..."
  }
}
```

桌面将 `AUTH_SESSION_INVALID` 映射到专用 Rust 错误与一个 `auth:session-invalid` 事件。一个幂等前端转换清除浏览器令牌与 Rust 令牌，重置账户/配额状态，并保留本地数据与 BYOK 凭证。上游 BYOK provider 的 `401` 绝不被解释为 OpenTypeless 账户失效。

### 23.6 最终 P1 数据契约

翻译配置向后兼容：

```text
translation.targets: 有序唯一列表，最小 1，最大 5
translation.active_target: targets 的成员
target_lang: active_target 的遗留镜像
```

词典导入有以下硬限制与保证：

- 仅 UTF-8
- TXT、结构化 CSV 与 JSON/备份打包输入
- 1 MiB 最大输入大小
- 10,000 最大行数
- 去重前 Unicode 归一化
- 变更前预览报告
- 一次数据库事务提交，任何写入失败即回滚
- CSV 引号加对 `=`、`+`、`-`、`@` 的公式前缀中性化
- 导出仅含词典词条与纠错规则

自定义应用映射持久化在专用的本地 `context-mappings.json`，与正常同步设置分离。候选值为生成范围限定，当之后的录音替换它们或应用退出时过期。持久化的匹配器类型限于：

```text
native_bundle_id | native_executable | exact_web_host
```

族到场景分配可进入显式设置备份。精确应用映射、候选值、进程身份、可执行文件身份、bundle ID 与主机被桌面允许列表序列化器与 TalkMore 递归备份净化器移除。

快捷键契约保持既有标量绑定作为兼容镜像，同时存储有序列表：

```text
dictationBindings: 有序列表，长度 1 到 3
askBindings: 有序列表，长度 0 到 3
translateBindings: 有序列表，长度 0 到 3
```

保存校验所有主、次角色间的重复绑定，校验当前平台的原生触发器支持，注册完整候选集，并在任何注册失败时回滚到先前的注册/配置。

### 23.10 发布控制与回滚

- `context_adaptation_enabled` 在保留正常润色的同时禁用自动应用风格。
- `voice_routing_flags.draft_insert`、`.rewrite_selection`、`.translate_selection`、`.search` 各自独立禁用单个命令路由。
- 删除或禁用本地应用映射立即恢复内置分类。
- 移除族到场景分配恢复自动族策略。
- 遗留 `target_lang`、`hotkey`、`ask_hotkey` 镜像允许旧读者保留主行为。
- 失败的快捷键注册恢复先前的已注册快捷键与先前的保存配置。
- 账户恢复是 TalkMore 拥有的轨道，不阻塞本地/BYOK 听写启动。
- 托管云端失效只清除托管身份/配额状态，且可通过登录逆转。

### 23.11 仍需的部署验证

实现与仓库门禁已完成。以下检查需要生产服务或物理操作系统界面，因此仍属发布操作者门禁：

1. 在生产 OpenTypeless 域名上验证一次实时 Resend 重置与密码更改邮件，包含一小时过期与一次性重用拒绝。
2. 在发布版 macOS 与 Windows 机器上运行参考应用识别矩阵，以及受支持处的 Linux X11/Wayland 回退检查。
3. 用实际外接键盘验证 Fn 与 RightAlt 原生组合，并在代表性原生与浏览器应用中确认焦点恢复。
4. 针对钉版本的托管模型/提示版本运行思想感知同负载矩阵，并记录模型、温度、语料版本与精确通过计数。
5. 在这些平台发布前，在 Windows 发布运行时与任何受支持的 Linux 打包目标上重复已完成的 macOS 900x700 与 720x480 视觉检查。

这些检查不需要额外的产品 UI 或云端数据收集。失败的检查阻塞受影响轨道的发布，并使用第 23.10 节的控制；它不静默削弱分类器、意图、隐私或账户契约。
